本轮继续实现完整项目，并沿用微软原生页面样式。实际产品操作只在指定 Windows Server 验收；本机执行源码构建和隔离测试。

## 问题与修复

退出时还原代理、启动时残留检查、启动冲突检查、启动提示和地域链接屏蔽这五个磁贴原先直接通过同步属性写入。新增回归先复现：存储抛出 IOException 时，异常从 RelayCommand.Execute 冒出点击边界，没有形成可观察的异步操作。修复前失败记录保留在 tile-preference-before.log 和同名 TRX。

五个磁贴现通过规范键 change set 等待 AppSettingsService 的实际保存，主控设置端口删除同步 setter。保存完成后刷新原磁贴对象，不提前显示未经保存的状态；同一磁贴正在保存时忽略重复点击。持久化失败显示错误，已经提交但通知失败时重读真实值并保留错误；再次点击根据实际值执行新的切换。调用者取消不报告成错误，独立的内部取消仍作为失败处理，嵌套致命异常继续传播。

上述五项和原有 TUN、自启、采样磁贴共八项切换，均由生产组合入口接入已有 MasterControlTileActionSession。它们与导入、弹窗和布局编辑共用页面有序队列。真正开始操作时才读取基线，避免使用先前导入前的过期值。页面离开撤销排队项和迟到点击，已进入不可中断提交的操作仍由队列持有并等待结束；下一次访问等待旧操作排空。

这一步继续使用现有唯一 LocalSettings 权威，没有增加第二套偏好存储。生产 JSON 权威、六类参与者、数据代际与全部消费者的整体切换仍未完成。
