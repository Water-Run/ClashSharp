## 项目结构与实现边界

解决方案包含 **19 个项目：11 个生产项目、4 个测试项目、4 个 Probe 工具**。技术基线为 .NET SDK 10.0.201、C# 14、Windows x64；主界面使用 WinUI 3，安装器使用 WPF。

| 层或进程 | 实现职责 | 维护重点 |
| --- | --- | --- |
| `ClashSharp.Core` | 领域模型、设置与服务协议、触发器及网络契约 | 保持领域与 UI 解耦，兼顾持久化和 IPC 兼容性 |
| `ClashSharp.Application` | 启动、生命周期、网络与数据变更协调、代际设置、触发器调度、MCP 用例 | 复用既有事务、取消、恢复和版本身份 |
| `ClashSharp.Infrastructure` | 文件、SQLite、进程和 Windows 平台适配 | 副作用保持在适配边界内，明确资源归属和关闭顺序 |
| `ClashSharp.Infrastructure.Mcp` | 本机 HTTP 服务器、凭据保护、请求生命周期 | 端点、权限、重试和退出行为与应用状态一致 |
| `ClashSharp` | AppHost 组合根、ViewModel、WinUI 页面、托盘和运行时适配 | 部分服务仍由组合根接入旧静态实例，迁移尚未全部结束 |
| `.MihomoService` 与 `.RecoveryWatchdog` | 特权服务内核、子进程监督、控制器代理及异常退出后的代理恢复 | 故障后核对代理、端口、TUN、服务和子进程状态 |
| `.Installer` 及 `.Installer.Core`、`.Installer.Presentation`、`.Installer.Windows` | UI、安装事务、展示模型、提权 helper、MSIX 与机器资源维护 | 普通构建使用预览运行端，真实维护走受控载荷与签名链路 |
| 四套测试与四个 Probe | 主程序、安装器核心、展示、Windows 适配测试；启动、进程、触发器、设置验证工具 | 单元测试与 Probe 结果保留各自范围 |

生产入口：[AppHost 组合](../../ClashSharp/ClashSharp/AppHost/ClashSharpAppHostFactory.cs)、[设置权威](../../ClashSharp/ClashSharp.Application/Settings/GenerationSettingsAuthority.cs)、[变更协调器](../../ClashSharp/ClashSharp.Application/Mutations/ApplicationMutationCoordinator.cs)、[生命周期登记](../../ClashSharp/ClashSharp.Application/Lifecycle/RuntimeLifetimeRegistry.cs)。

## 分阶段推进

### 第一阶段 修复基础链路并统一手验候选

DEV-01 已完成。按用户新增反馈推进 DEV-04：导入兼容与操作流程、Mihomo 最新稳定输入、全程序通知级别、真实管理员会话兼容和失败去重均已实现，准确完整 CI 已通过；最终签名候选、蓝机实测和桌面交付已完成。继续沿用既有 Server 2025 与 CI 范围，不增加重复的 Windows 11 验收矩阵。

11 月 2 日优先手验 URL／本地文件／拖放导入、失败重试与显式启用，默认／仅重要／详细／关闭四种通知策略，及真实节点与代理模式。用户反馈继续记录候选、步骤、预期和结果；正式发布准备和后续架构维护分别推进。

### 第二阶段 修复反馈并交付统一候选

1. 按网络可用性／数据安全、功能阻断、交互与样式的影响排序处理反馈，每项保留复现和完成标准。
2. 合并图标修正与确认的修复，完成相关回归与准确源码 CI，再生成内部签名候选。
3. 核对身份、载荷、原 ZIP 摘要和安装内容；更新前保护最新数据，通过正常安装器维护并复验实际变更。
4. 更新手验清单并交由用户确认反馈结果，新增反馈继续按同一流程处理。

阶段出口：DEV-02、DEV-03 和本轮 DEV-04 关闭，源码、CI、签名候选、服务器安装和交付 ZIP 对应同一最终产品内容。

### 第三阶段 完成正式发布条件

用户确认后完成 DEV-05：核对正式发布者、证书链、时间戳与材料清理；通过发布保护预检和实际审批；检查最终版本、安装维护、第三方材料、发行说明与校验和；发布时核对同一产物与来源身份。输入和约束沿用[安装器说明](../../ClashSharp/Installer/README.md)及[发布保护预检记录](2026-10-27-release-protection-preflight.md)。

阶段出口：正式产物取得用户确认并通过真实发布流程。内部自签产物不直接转为公开正式版本。

### 第四阶段 按使用证据迭代

推进 DEV-06 至 DEV-08。性能基线包含冷启动、配置切换、大量订阅／连接／日志下的 UI 延迟、内存、SQLite 大小与查询耗时；记录输入规模和环境后制定优化目标，再拆分高频修改区域，决定精确统计与 DNS 诊断的范围。
