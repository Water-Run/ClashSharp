# 当前数据目录的完整清理检查点

此检查点基于私有提交 `84a6136de7a5d58ddedac42f29427ab4ecdb565b`。设置页的“清除全部数据”此前通过 `ApplicationActionService` 调用旧维护单例；绑定统一设置服务后，旧的同步偏好写入会被拒绝，而且构造旧维护单例会引入不属于当前数据目录的采样、日志和配置缓存。

生产入口现改为主机注入的 `IApplicationDataClearOperationFactory`。`GenerationDataClearOperationFactory` 验证当前数据目录确实属于主机配置的应用数据根，再将完整维护操作交给已有的进程生命周期。页面不会内联停止服务或删除文件；取消及未被接受的退出请求都不会开始清理。

维护继续沿用“验证停机、清理主机数据、释放主机和进程写入者、删除文件”的顺序。新工厂在终态许可下先删除并确认控制端凭据，再清空旧迁移来源。凭据删除失败时，旧偏好和所有数据文件均保留。旧来源的清空只允许匹配主机的终态独占许可，不是另一个设置修改入口，不改写当前 JSON 会话，也不向已停止的消费者发布偏好变化。删除回复失败时会检查实际结果，不能把仍存在的值报告为已清除。

旧迁移来源一并清除，是为了防止删除数据目录后，下一次启动又从 Windows 旧设置导入原偏好。实际仓库在主机释放之后随应用数据目录统一删除，包括当前目录、历史目录、配置、日志和触发器持久状态。

`DataGenerationManager.IsDisposalComplete` 只有在所有拥有的仓库和生产者均成功释放后才成立。文件清理增加此条件；正在释放或释放失败均不允许开始删文件，失败清理完成后可以重试。目录检查现在包含祖先路径，拒绝通过祖先符号链接进入应用数据根之外的位置。
