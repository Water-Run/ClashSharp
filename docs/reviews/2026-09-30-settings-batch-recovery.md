# 设置批量写入失败后的恢复

2026 年 9 月 30 日检查正式程序的设置保存、重置与导入路径，修复了两处进程内恢复缺陷。此批代码基于 `650e1d6` 后续工作树；生产偏好仍由 `AppSettingsService` 和 Windows LocalSettings 管理，尚未完成 JSON 设置权威与数据代际的整体切换。

原实现只有在单个存储调用成功返回后才登记回滚项。如果存储已经修改或删除了值，随后报告错误，该键会漏掉恢复，造成同一批设置混合新旧值。回滚本身还会在第一个恢复错误处结束，使其他能够恢复的键保留新值。

现在在每次调用存储之前保存该键的旧值，错误发生后按逆序恢复所有已经尝试过的键。单个恢复失败不会跳过剩余键，原始错误与全部恢复错误一并返回；未完整提交的批次不发送设置成功通知。页面取消和独占操作请求仍须等到当前批次及恢复结束。

存储访问统一经过一个 `IDictionary`。生产继续使用原来的 Windows 存储映射；测试通过内部构造函数注入独立内存存储。共享实例改为首次使用时初始化，因此创建这些隔离实例不会打开 Windows LocalSettings。

新增十五项故障场景：首次写入和覆盖已有值时丢失成功回执，写入前拒绝，重置删除后报错，多键恢复失败，页面取消期间排空，以及地区设置别名恢复。旧恢复实现 **15 项中 12 失败、3 通过**；修复后的相关回归 **189 项通过，零失败、零跳过**，包含全部十五项新用例，并覆盖设置页面、导入导出、启动与采样设置以及生产装配门禁。

本地证据位于 `artifacts/verification/settings-batch-20260930`：`settings-batch-before-fix.trx` 保存原始失败，`settings-batch-after-fix.trx` 保存修复后的逐项结果。完整 18 项目 Release x64 构建成功，28.33 秒、零警告、零错误；完整 x64 格式检查通过，退出码 0。`verification.json` 核对两份 TRX 的逐项结果、十五项新增用例和三个相关源码散列，确认代码在最终测试开始后未改变。

末次核对发现共享工作区的首页和统计页文件于 03:00 UTC 另有修改，晚于本轮构建和格式检查。上述检查证明的是验证当时的源码，不覆盖这些后续页面改动；本批三个设置源码文件的散列仍与回执一致。

这些故障通过隔离存储注入，证明代码在不确定写入结果下的恢复行为，并不代表实际 Windows 存储发生过相同错误。若存储持续拒绝恢复，程序会报告恢复不完整，无法保证所有值都已还原。进程中断后的原子恢复仍属于整体代际切换的未完成范围。

本机未启动应用或安装器，也未改变产品设置。此批没有新增蓝色服务器原生验收，设置保存、重置与导入还需在同一安装候选上实际复测；页面样式、全部磁贴、安装器及整体生产验收的待办状态保持不变。
