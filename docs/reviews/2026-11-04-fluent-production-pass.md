# Fluent 样式、交互与通知收敛（2026-11-04）

用户要求以 WinUI 3 原生体验为准，重做关于页和统计页，优化订阅、配置、设置等日常场景及安装器，并在蓝机实机验收；随后补充要求把问题从根源上解决到可发布水平。本页记录两轮实现、根因证据与交付状态。

## 视觉与布局规范

- 页内设置卡片统一为 `ControlCornerRadius`（4 DIP），间距 4 DIP，首列为 20 DIP Fluent 图标，分组标题共用 `ClashSectionHeaderTextBlockStyle`；图表、排行和身份头等大面板使用 `OverlayCornerRadius`（8 DIP）。主控 Metro 磁贴、主状态卡和模式按钮保留直角 `ClashCardGridStyle`，不在本轮改变。
- 关于页参照 Windows 设置“关于”：身份头卡片、带“复制”的应用信息卡（版本含源提交、编译时间、内核、运行时、本地代理、作者、许可证），以及更新、本地代理、GitHub、mihomo 相关行。编译时间由 Core 程序集的 `ClashSharp.BuildTimestamp` 元数据提供，按用户时间格式显示。
- 统计页改为四个指标卡、单序列近 14 天柱状图（按本地日历补零、逐日提示、峰值注记、无图例）和三个原生进度条排行卡；日志入口为设置卡。
- 配置页为当前配置卡与订阅导入卡，列表中“当前使用”为强调徽章；双击或回车即设为当前。配置历史改为原生版本列表，逐项显示时间、来源及节点／规则数或不可恢复原因。链接页使用卡片内原生列表，显示配额进度条。
- 设置页 37 张卡片均有图标；登录时代理恢复“检测”显示进度与结果行，注册／移除按实际状态启用。MCP 组：权限展开器与卡片同构，“应用更改”和端点并入运行状态卡，客户端配置提供“显示配置”与“复制”。

## 剪贴板根因

用户经 RDP 实测“复制客户端配置”报“未能写入剪贴板”。蓝机提权交互会话（与应用同为提权、RDP 客户端已连接）中的独立探针结果：`SetContentWithOptions` 返回成功，`GetContent` 回读 4 次均一致，而 `Clipboard.Flush()` 抛出 `COMException 0x800401D0`（`CLIPBRD_E_CANT_OPEN`）；剪贴板所有者为 `rdpclip`。连接的 RDP 客户端在每次剪贴板变更后短暂打开剪贴板转发格式，单次 Flush 冲突即被当成整体失败。此前 996 的成功实测是在 RDP 断开时完成，因此未暴露。

修复为共享 `ClipboardTextWriter`：只对 `CLIPBRD_E_CANT_OPEN` 做有界退避重试（最多 10 次），写入、Flush 与回读三步分别处理；其他错误原样上报。MCP 继续排除剪贴板历史和云同步，关于页复制使用同一实现。

## 通知级别

“默认”过多的来源是被动探测（打开关于页或主控的更新检查、公网 IP 探测）按失败上报，以及用户在窗口内操作时重复弹出系统通知。新策略：

| 类别 | 仅重要 | 默认 | 详细 |
| --- | --- | --- | --- |
| 关键问题：内核意外退出、代理或服务不可用、启动检查需要处理、数据恢复 | ✓ | ✓ | ✓ |
| 重要结果：操作失败、代理模式／TUN／端口变化、发现新版本、服务恢复 | — | 仅当 Clash# 不在前台 | ✓ |
| 常规反馈：导入、保存、测速等成功；更新检查与公网 IP 探测结果 | — | — | ✓ |
| 触发器通知动作 | — | ✓ | ✓ |

前台判定来自主窗口激活状态；最小化、隐藏到托盘或切到其他窗口即视为后台。关键事件和“详细”级别不受前台过滤。设置页与安装器均提供可展开的级别内容表；安装器“跟随系统环境”可展开查看将写入的初始偏好。按类别单独开关会改变设置结构、数据包、MCP 规则和安装器交接，本轮未纳入。

## 安装器

设置卡改为 4 DIP 圆角与 4 DIP 间距，分组标题降为 14 SemiBold；每页仅一个强调按钮（维护页“修复”为主，“启动 Clash#”为普通按钮；完成页“启动 Clash#”为主）；强调模板不识别访问键，改用 `AccessText`，不再显示“(_L)”。
