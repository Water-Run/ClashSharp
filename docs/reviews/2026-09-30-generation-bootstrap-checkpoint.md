## 已实现

`DataGenerationBootstrapper` 在独占许可下读取持久 manifest。只有确认为首次启动时才创建候选；候选完成全部仓库打开后才发布并交给 `DataGenerationManager`。已有 manifest 直接打开其仓库，不再读取旧偏好。发布失去回执时重新读取磁盘结果；取消不能跳过这次结果确认。另一启动抢先发布时释放本次候选容器，再打开实际获胜的目录。损坏 manifest 或尚无法确认的结果不会激活数据访问入口。

`LegacyDataGenerationPreparer` 保留旧目录，复制配置目录、历史版本、目录元数据、日志和触发器数据。SQLite 使用备份 API 取得包括已提交 WAL 页的快照，并检查候选数据库完整性；未直接复制仍在使用的数据库主文件。触发器迁移意图一起保留。旧控制端凭据、生成的运行配置及无关文件不进入偏好迁移。失败候选保留为未发布目录，重试分配新的身份。

主程序新增 `AppDataGenerationFactory` 和 `AppDataGenerationRepositories`，使用真实的设置 JSON 会话、`ProfileCatalogService`、`LogStorageService`、`CoreConfigurationService` 和 `SqliteTriggerRepository`。首次打开之前等待旧事务恢复；发布目录中的仓库丢失、数据库截断、配置目录 JSON 损坏都会阻止打开，不会重新建成空库。容器要求六类设置参与者齐全，并拥有其后台生产者及释放顺序。

配置选择的持久提交端口已改为异步。完整操作等待设置提交及失败补偿，配置仓库退休也等待这些工作结束。容器先停止生产者、排空配置仓库，再释放设置会话、设置参与者和日志依赖。停止失败时保留依赖以便重试。
