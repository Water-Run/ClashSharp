# 安装维护恢复基础能力检查点

本检查点接续[维护恢复设计](../design/2026-10-01-installer-maintenance-recovery.md)，完成原服务基线、首次捕获存储与受验证 guard 约束的服务恢复能力。生产 helper 尚未调用这些能力，也没有新增恢复按钮；G01 的完整用户恢复功能继续实现。

服务基线绑定准确 Repair 的初始 Prepared 意图、归属准确的固定服务配置及 DACL，保留 Running/Stopped 稳定状态，不以 PID 判断恢复身份。规范私有 JSON 限制 64 KiB，拒绝缺失、重复、未知或非规范内容；服务依赖复制为只读集合，序列化和 I/O 临时字节使用后清零。服务命令行内的 IPC 凭据不能进入普通事务、父进程 IPC、日志或界面。

存储使用认证权限作用域中的固定私有文件与读/写目录 guard。准确首次捕获后重放零写入，另一事务或原始观察不能替换已有基线；异常或取消后独立重读确认提交。缺少目录时只读路径不创建文件。暂未开放删除，防止尚未完成的恢复终结流程丢失证据；本地 gate 不替代跨进程机器权限。

服务恢复要求显式原安装验证 guard。验证失败前零 SCM 写入，只接受准确已恢复状态或归属准确的准备状态。原配置复原后再次核对原包、载荷、关联和证书证据，才允许启动；最后核对完整配置、DACL及运行状态。配置或启动回执丢失仍通过实际状态确认；写入接收后的 UI 取消不会遗弃恢复观察。配置无法到达原状态时保留不确定结果，不启动服务或宣称事务已终结。

## 仍需完成

私有服务基线还必须与原包、全部机器载荷、关联及证书的实际证据组合；原安装 guard 必须持有准确权限和目录/文件租约。随后接入可重启恢复决定、阶段执行、公共事务终结与明确用户入口，并完成真实中断/取消/回执丢失矩阵。原恢复证据缺失、包已改变或状态不能确认时仍应使用同候选继续完成更新。

证书轮换、活动网络下数据维护、窗口状态、完整页面及磁贴矩阵、正式发行仍属于原目标。此检查点不声明产品恢复或全项目完成。
