# 设置页异步偏好入口（2026-09-22）

设置页的普通偏好编辑已接入实际生产调用。版本保持 `1.0.0`；本地和远端继续只使用 `main`，没有开放 PR。完整 JSON 设置权威与数据代际切换仍在推进，本批没有启用第二套偏好存储。

## 实际行为

- 语言、主题、强调色、启动策略、关闭行为、通知、托盘、地区显示、触发器开关及连接测试地址共 21 个规范键通过可等待的 change set 写入。基本、通知、触发器、托盘、Windows 策略及地区显示六类分组重置也使用可等待入口。
- 页面使用单向绑定显示已提交值，通过原有 `PageOperationSession` 接收并串行等待编辑。写入过程中禁用偏好输入；页面离开会取消排队操作，等待已开始操作结束。新的页面访问等待旧队列排空，旧访问不会重新绑定新访问的控件。
- 自定义颜色的模式与色值、三项连接地址及整组重置均先更新完整视图模型字段，再通知观察者。后续编辑不调用整页 `Load()`，保留原有重启基线和无关的网络、采样草稿。
- 持久化失败保留错误提示。若写入已提交、后续通知失败，页面重新读取同一锁下的完整实际偏好，显示保存结果；不会把失败的主题效果标记为成功或擅自再次执行它。致命异常仍传播。
- 兼容存储在申请 mutation admission 前复制并校验规范键、类型和取值，拒绝重复键及旧别名写入；批次发布和全部通知期间持有许可。提交开始后不因页面取消而截断。地区模式继续维护旧布尔别名，分组重置删除相应规范键及别名，直到整体迁移替换该存储。
- 连接地址草稿与写入使用相同 registry 校验，包括长度和 URL 凭据限制。托盘编辑器保留“全部取消选择后恢复默认菜单”的既有行为。

控件恢复值时重新建立单向绑定，而不是以本地属性值替换绑定；先清除旧绑定再调用 `SetBinding`，顺序遵循 [WinUI 官方说明](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.frameworkelement.setbinding?view=windows-app-sdk-1.8)。此操作仅在当前页面访问仍有效时执行。

## 验证

使用固定 SDK `10.0.201`，18 项目 Release x64 构建通过，零警告、零错误；完整 format 检查 1548 文件，零变更、无工作区加载警告。四组本机测试共 **5233 / 5233**，零失败、零跳过：主程序 2972、Installer Core 1022、Presentation 143、Windows 安全集 1096。相比前一主线新增 **34 项**回归并全部实际执行。

新增行为回归覆盖延迟写入、失败、提交前取消、提交后排空、排队撤销、输入快照复制、成组通知、重启基线、通知回执失败后的重读、空托盘选择及编辑器/写入校验一致性；存储回归覆盖完整批次、许可寿命、非法键/类型、别名兼容和取消。页面架构检查限制双向绑定只用于原有五个运行时草稿控件。

首次全套检查发现额外 View 分部文件违反既有目录约束，事件处理已合回 `Settings.xaml.cs`；两项旧资源检查改为验证实际等待的异步调用。目录与单一设置权威门禁继续保留。

本机日志与 TRX 位于忽略目录 `artifacts/verification/settings-preferences-*`，构建日志为 `settings-cutover-build.log`。本机 Windows 测试集继续排除实际证书存储类与原生目录清理类，后者由隔离 CI 执行。

## 下一步

`AppSettingsService` 的 LocalSettings 仍是生产唯一偏好权威，现有同步兼容接口尚未删除。启动任务、采样和网络仍由原有异步协调器处理；导入、全设置重置与数据清理仍使用现有事务。页面偏好现在具有实际使用的可等待入口，但这些入口尚未统一到 `ISettingsAuthority`。

继续将页面、磁贴、触发器、网络提交者和所有读取消费者切到同一代际会话；一起装配六类设置参与者及 Profile/Log/Trigger 服务寿命，接通迁移、导入、重置、回滚和退出排空，再原子替换临时架构门禁。完整候选的 WinUI 交互、代理/TUN、安装器故障恢复与正式签名验收仍须完成，详见[设置设计](../design/2026-09-08-settings-generation-cutover.md)及[开发状态](2026-09-22-development-status.md)。
