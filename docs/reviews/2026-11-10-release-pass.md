拍摄中发现并修正的问题：

- 连接页含这台机器自身的后台连接（Windows 服务和其他程序的域名），不能入库。拍摄前改为在搜索框输入 `aliyun`，只显示演示镜像的连接。
- 自动化导航在窗口激活时会画出键盘焦点框。拍摄前先做一次真实鼠标点击空白处，WinUI 随后按指针输入处理焦点，不再画框。
- 模式按钮只支持 Invoke，读不出选中状态。此前每页日志里的“重新套用规则接管”是对同一模式的盲目重复点击，并非检测到模式变化；现已改为只检查状态、不再点击，拍完逐张核对。
- 约四分之一的图标题栏是灰的（语言切换后窗口失去前台）。现在每次截图前先激活窗口。
- 这台机器的显示区域后来变高，窗口默认可以到 1720 像素高，与此前的 1630 不一致。现在显式固定高度，整套图尺寸相同。
- 托盘图标的自动化 ID 是 `NotifyItemIcon`；任务栏上同名的“1 个运行窗口”按钮是应用按钮，右键弹出的是跳转列表，不是应用自己的菜单。重复点击展开按钮会把溢出窗口收回去，所以每次尝试都重新定位图标。

## 已知问题与边界

- **正式发布**：仍缺正式签名配置和受保护的发布环境（DEV-05）。CI 包和内部候选均为测试签名，不能代替正式发布。
- **旧 MCP 端口**：新安装的默认端口是 20000，但用户已有的数据里保存的是旧端口 17892，升级不会改它。是否要把旧默认值迁移到 20000 是产品决定，本轮没有做。
- **覆盖率**：最终覆盖率没有重测，需要用户同意后再跑（上一次被内存保护终止）。WinUI 视图胶水代码（约 6 千行 View／Components）没有自动化覆盖，由实机截图和验收补位；Watchdog 与 Presentation 组合层覆盖仍偏低。
- **一次未解释的模式切换**：11 月 10 日上午 10:40 的截图轮中，应用曾从“规则接管”切到“禁用”。用空操作和仅导航的脚本均未复现，同时段没有远程桌面会话事件，原因未查明。事后复查了蓝机上保存的应用日志：那一轮会话（候选刚装好、尚未做数据保护）的日志没有保留，无法回溯；但此后保存下来的两段演示会话（11 月 10 日 13:51–14:40 的八语言截图轮、21:09–21:41 的验收轮）和用户真实数据的日志里，规则接管只在脚本操作时切换，没有一次未解释的切换。所以它没有再出现，但原因仍未知。
- **前台时的通知抑制**：按设计，应用窗口在前台时部分通知不会弹出；这一点没有在真机上专门验证，拍摄 toast 时用“更多”级别保证窗口在前台也有 toast。
- **MCP 连接重置**：第一次验收里，通过 MCP 修改透明代理偏好的那次调用，连接被对端重置，随后设置已生效。只是一次观察，没有查清是服务重启核心造成的还是别的原因，也没有复现。
- **波斯语标题栏**：内容区整体镜像，但应用标题栏在 XAML 中固定为从左到右，关闭等按钮仍在右侧，与 Windows 在从右到左语言下镜像标题栏的习惯不同。本轮未改，列为后续项。
- **波斯语数字**：界面里的数字有的显示为波斯数字（目录原文，如“۶۰ 样本”），有的显示为拉丁数字（格式化的流量值，如 `111.79 KB`），没有统一。本轮没有判断是否需要统一，列为后续检查项。
- **原生安装器测试**：9 项证书／目录原生用例在开发机上按设计跳过，只在一次性 CI 中执行。
- **截图中的数据**：文档截图使用本机回环上的合成演示订阅，节点地址均在 RFC 5737 测试网段，流量来自走直连规则的公共镜像下载；不含任何真实订阅、令牌或用户数据。
- **后台截图**：截图由 UI 自动化完成，会移动鼠标并抢占前台窗口，一台 Windows 会话同一时间只有一个交互桌面，无法在设备被使用时放到后台运行。需要在用户不使用设备时执行。
