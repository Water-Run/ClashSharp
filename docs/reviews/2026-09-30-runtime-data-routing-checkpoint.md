# 配置、日志与节点选择的当前数据目录接入

基线为私有开发节点 `89d2e0ccbc0bf5fdb922016257150305adf8800e`；主线仍为 `b70a1538ddd8e722abefa7635b909ffbbedf2b73`。整体设置迁移尚未完成，此节点不作为发布候选。

## 实现

原生服务工厂现在持有由应用运行实例绑定的稳定配置、日志和节点选择入口。每次操作通过当前数据代解析实际仓库，同步文件读取及完整异步操作均持有该代，直到返回结果或失败。页面、网络接管、配置解析、规则命中、延迟记录、托盘、通知和启动服务使用这些入口，避免单例固定在旧目录。配置解析读取完整文本，不再先返回路径后在目录所有权之外读取文件。

顺序为 25 的延迟启动步骤安装入口绑定，早于数据事务恢复；只构造后立即停止应用不会安装绑定或创建这些原生服务。绑定由主机释放，重叠运行实例被拒绝，旧实例的重复释放不会解除新实例的绑定。绑定之前或释放后访问失败；数据代已关闭、退休或排空期间，不会重新启用旧目录。

仅尚未初始化数据代的启动恢复允许访问旧配置、旧日志和旧节点选择仓库。每代实际节点选择服务使用同一组修改许可和执行顺序，选择、控制器确认及持久化作为完整操作持有目录。首次迁移补充复制 `mihomo/proxy-selections.json`；新目录的后续选择不会改写保留的旧文件。

网络切换前的最后流量结算也通过当前代的实际采样器执行；启动恢复阶段仅使用已创建的旧采样器，不会为清理而创建它。原生结算效果仍待蓝色服务器验收。

## 验证

新增 **8 项**回归全部通过，逐项结果见 `new-regressions.json`：

- 从真实旧节点选择文件恢复，随后只向新目录保存。
- 同一组配置、日志和节点选择入口跟随提交后的目录切换，保留旧文件不变。
- 配置导入在验证、提交和失败处理完成前阻止退休，成功及失败两种情况均释放所有权。
- 节点选择等待控制器确认并完成持久化后才允许退休。
- 旧目录回退仅限初始化之前，关闭后不能恢复旧仓库。
- 重叠绑定被拒绝，重复释放旧绑定不干扰新绑定。
- 节点选择文件位置被目录占用时迁移明确失败，不静默丢弃记录。
