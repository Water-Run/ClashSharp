## 原生缓冲区失败的独立复现

[HIGHCONTRASTW 官方合同](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-highcontrastw)说明由系统返回方案名缓冲区并使用 LocalFree 释放，且切换高对比度时不使用 HCF_OPTION_NOTHEMECHANGE。此前辅助程序出现 0xC0000374，本轮以独立 x64 C++ 进程核对原生行为，没有依赖 .NET 封送，也没有执行任何 SPI_SET 或访问产品数据。

四次 GET 返回相同地址；只读遍历当前进程四个堆，返回地址匹配一个忙块的起点，遍历失败为零。自有 LocalAlloc 正对照同样匹配一个块，正常释放。该结果比 MEM_PRIVATE 分类更具体，但仍不等于每次 GET 都授予独立释放责任。

另两个独立子进程按官方描述执行释放：一次 GET/Free 正常退出 0；连续两次 GET/Free 在第二次释放前记录到 flags126，随后退出 0xC0000374。该失败单独保留，不把父任务成功收集报告当作子进程通过。这里证明指定服务器上的重复调用路径可复现旧失败，不推断其他 Windows 版本或所有调用顺序。

后续验收辅助程序在短生命周期进程中保留 GET 返回值及 SET 输入直到进程退出，不在同一进程重复释放该缓冲区。产品自身没有新增该 Win32 路径。首轮独立探针构建因常量条件触发 /WX 而拒绝；改用 static_assert 后编译成功，原失败日志保留。
