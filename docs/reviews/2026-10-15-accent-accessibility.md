# 自定义强调色与系统对比度验收

## 已确认的问题和实现

旧版 `381503d` 将自定义强调色配上固定白色文字。真实界面选择白色后，颜色选择器的确认按钮成为没有可见文字的白块；7 组颜色回归全部失败，原蓝色悬停状态的文字对比度约为 2.829:1。

`2688d0c` 为普通浅色、深色保存独立的 ARGB 值，按实际填充选择黑/白文字，并调整悬停与按下填充，使共用的前景仍可读。链接文字根据内容背景调整，偏好中保留用户选中的原颜色；已经存在的控件通过当前 UI 线程中的主题刷新重新解析资源。正常文字的受测目标采用 [WCAG 2.2 对比度要求](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)的 4.5:1，包含普通、悬停、按下及选中状态。这不等于整套应用已通过 WCAG 审核。

首个候选虽然通过 CI，但原生控件显示了系统颜色，未保留选中的白色，不能计为修复通过。原因是 WinUI 在当前字典中先查询合并字典，再查主题字典。`0088752` 改用位于系统控件字典之后的独立合并字典，并在读取时核对字典归属和优先级；其浅色、深色值先于框架解析，高对比度字典保持无自定义覆盖，继续回退系统颜色。依据见 [WinUI 资源查找设计](https://github.com/microsoft/microsoft-ui-xaml/blob/main/docs/design-notes/resources.md#resource-reference-resolution)和[系统对比主题指南](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/high-contrast-themes)。

`75a4762` 进一步覆盖导航选中标记、进度条/环和开关旋钮的直接资源键。标记使用与页面背景对比的颜色，旋钮与按钮文字使用与填充对比的颜色，避免间接资源别名仍使用旧的系统前景。完整资源合同为 **55 项：7 个颜色值、48 个画刷**。三项集成测试的完整资源数量随合同更新，原有失败、恢复和独立观察断言保留。

`ae4ec1b` 修复最小窗口中颜色选择器的尾部字段裁切：明确的垂直滚动区随 `XamlRoot` 高度调整，保留标题和底部操作区，关闭时解除尺寸变化订阅。同一版把开启状态开关边线改为与页面对比的颜色，但实图仍没有边线。固定 WinUI SDK 模板的 `ToggleSwitchOnStrokeThickness` 在普通主题中默认为 0，因此 `6ea751a` 将其设为 1 DIP；系统高对比度默认值本来就是 1。最后这一笔画宽度修正仍需准确新包实图确认。
