## 已执行流程

- 安装器默认窗口、展开详情、最大化、点击安装、完成、重新检查、正常关闭。安装后账户包注册成功，产品服务运行，六处目录创建。
- 应用正常首次启动、启动引导、默认浅色、切换深色、最大化、主控与关于页面。
- 使用原生文件选择器导入本地配置，校验，设为当前，并在节点页读取运行时策略组。
- 待命模式下，真实 HTTP 和 SOCKS5 入站请求均直连，原生用户系统代理保持关闭。
- 按规则接管后，真实 HTTP 和 SOCKS5 入站请求均通过测试代理；在节点页将规则组切换为 DIRECT 后，实际请求立即直连。
- 持续传输在连接页显示目标、路径、规则和流量；统计页聚合配置、日期、节点数据；从统计页打开系统日志。

网络验收使用服务器回环地址上的受控 HTTP 源站和代理。代理仅允许自己的测试源站；同时支持 HTTP 转发及 CONNECT。最初只支持转发的夹具被 mihomo 的 CONNECT 请求拒绝，此阶段失败不归因于产品，修正夹具后重新验证并保存了新的结果。

## 第一批发现与修复

以下源码修复已加入本轮候选，目标服务器的新包复测尚未完成。

| 问题 | 修复与复测要求 |
| --- | --- |
| 系统代理界面显示开启，原生用户注册表仍为关闭 | MSIX 清单仅将当前用户 Internet Settings 键排除写入虚拟化；新包必须验证原生代理生效、退出恢复及卸载后无遗留 |

| 安装完成后详情仍显示安装前状态 | 失效就绪快照时同时清空陈旧能力行；重新检查后显示最新结果 |

## 第二批实测与修复（9 月 23 日）

- `b5bb453` 的两项 CI 作业均通过；目标服务器也完成该提交的生产安装包构建。因继续发现退出阻塞问题，尚未安装此中间候选。
- 日志分类选择后仍显示原来的全部记录。搜索及两类筛选的双向绑定抢先更新了 ViewModel，使事件处理器误判无需加载；改为由事件负责更新，并在数据源变化后恢复筛选选择。离开连接页的 WebSocket 取消只在所属传输边界归一化，保留真实传输错误。
- `c4ed46e` 两次托盘安全退出均失败，随后点击未启用模式也失败。日志为 `mutation-compensated`，应用仍运行，内核被补偿逻辑重新启动。源码定位到目标状态仍保留正在使用的 ClashSharp 代理地址，而释放代理实际还原了原始地址，验证因此误判。修复以所有权日志预测释放结果，涵盖空地址、原有关闭代理、原有启用的其他代理和旧版端点；退出失败时恢复窗口并显示可关闭的提示。
- 为完成旧包维护验收，记录现场后对精确核验过的测试应用进程执行受控崩溃。应用与内核均退出，代理所有权日志自动清除。此项不计作正常退出通过，也不能代替新包原生系统代理恢复测试。
- 使用安装器点击修复完成，随后点击卸载完成。外部快照确认产品包、服务和六处产品目录均为零，安装器管理的测试发布者信任证书已移除，系统代理关闭。一次取消按钮点击发生在修复已经结束之后，不计作取消流程覆盖。

第二批网络还原、日志与传输修复完成后，18 项目构建零警告零错误，主程序 **2985 / 2985** 回归通过，格式检查通过；随后增加退出失败提示，最终构建仍为零警告零错误，相关界面、架构与本地化检查 **438 / 438** 通过。所有第二批修复仍需新包实机复测。
