# 外部代理变化后的所有权日志收尾

准确 `57cc223` 候选在还原已手工恢复注册表、但仍保留旧代理所有权日志的闭合数据后，普通启动未能应用网络设置。31 项设置变为 27 已验证、4 未验证、1 项待处理，稳定错误为 `settings.application.probe_failed`。独立认证服务探针确认服务正常且没有核心，失败来自未收尾的代理日志，详见[登录实机记录](2026-10-07-login-recovery-composition.md)。

## 修复

旧启动恢复只检测当前代理是否仍启用并指向本程序端口。用户或外部程序关闭或替换代理后，日志仍在，但恢复被跳过；运行状态核验要求日志已释放，因此不能建立干净的未运行基线。新恢复决策同时检查有效所有权日志，仍尊重“启动时检查代理残留”偏好。清理继续经过现有恢复事务和逐字段所有权合并。

回归还发现只有布尔开关相等不足以证明代理开关归属：外部程序安装不同代理服务器并保持启用时，原逻辑会将其关闭。恢复现在要求当前手动服务器匹配已应用或待应用记录，才还原启用开关。部分写入阶段仍接受记录中的旧、新服务器，因此写入开关后、尚未写入服务器时的崩溃可以恢复。其他字段保持原逐字段合并；再次接管会使用已有合并逻辑保存新的外部基线。

新增十项回归覆盖关闭代理、外部服务器、不同回环端口、没有日志的外部状态、重新接管后的外部基线，以及写入开关后的中断。原决策下五项失败、三项通过；仅修复决策后七项通过、外部启用开关保留一项仍失败，准确重现错误关闭。补齐服务器归属约束后，相关集 118 项、主程序全量 4,018 项全部通过，18 项目 Release 构建零警告、零错误，格式通过。一次测试夹具使用只读属性初始化导致编译失败，已改为通过真实写入接口建立日志。

## 待验

准确新候选仍需验证已关闭代理日志的自动退休，以及外部启用代理替换后的注册表状态保留。原 `57cc223` 的正常退出和显式重试已作为测试恢复保留，不作为本修复自动恢复的证据。正式版本保持 `1.0.0.0`；内部验收签名与正式签名仍分开记录。
