# 基础导入流程与通知系统修正

用户计划 11 月 2 日继续手验，要求先修好基础使用链路、优化导入体验、升级 Mihomo，并按不同级别覆盖整个程序的通知。本轮沿用原 Server 2025，通过公网 SSH 验收，不增加另一套 Windows 11 环境。

## 配置导入

参考 [Clash Verge Rev 的配置导入说明](https://github.com/clash-verge-rev/clash-verge-rev.github.io/blob/main/docs/guide/profile.md)和[配置编辑器实现](https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/src/components/profile/profile-viewer.tsx)，将订阅 URL 和本地文件入口放到配置页。粘贴链接后一次完成保存、下载和校验，名称可选；文件可通过选择器或拖放导入。失败保留 URL 草稿及已保存链接，重复导入同一 URL 复用链接。成功选中导入结果，显示节点、规则数量和“设为当前”入口，保持当前配置与代理模式，等待用户明确启用。

旧链接页的“添加”也接入立即下载，避免只保存一个链接、还需要另找更新按钮才能得到配置。链接管理及定时更新继续保留。

本轮定位了三项真实逻辑缺陷：

- 行首字符串扫描把引号键、行内映射、整体缩进等合法 YAML 当成缺少配置章节，并把 `proxy-groups`、`rules` 等可选字段当成必填。改为读取 YAML 根映射、识别配置内容，最终由实际内核校验；无关格式与异常 YAML 继续拒绝。
- 全局 `Trim()` 会只移除第一行缩进，破坏合法文档，也会改写末尾字面量内容。现在仅规范行尾和 BOM，保留 YAML 的有效空白。
- 内核文件缺失时曾直接返回，相当于跳过校验。现在明确失败，不再报告配置有效。

节点和规则预览优先读取同一语义文档，保持引号键、行内映射等写法下的计数；损坏历史文本仍保留既有尽力预览路径。

修正前新增的 7 项回归全部失败。原蓝机上的真实新版内核对引号键、行内映射、精简规则配置和整体缩进四份样例均以 0 退出，证明这些输入本来就受内核支持。修正后的定向检查为 634 通过、0 失败、0 跳过。

全量应用测试首轮为 4,789 通过、5 失败、0 跳过：三项旧导入成功文案断言、一项未实现下载的旧假目录，以及一项保存完成后取消却继续调用下载的边界。原失败报告保留；新增阶段间取消检查，更新假目录及反馈断言，并区分首次导入与更新当前配置。修正后的生命周期、通知、导入兼容等 159 项定向复核全部通过。该定向报告不替代最终源码的完整 CI。

19 项目 Release/x64 构建零警告、零错误；安装器核心 1,141、展示 206、Windows 本地安全集 1,361 项通过，另 13 项隔离测试留由托管 CI 执行。62 个跟踪 PowerShell 源码解析通过。证据位于忽略目录 `artifacts/verification/basic-readiness-20261101/`。

## 通知级别与覆盖

通知成功以 Windows 接受请求为前提：发送后检查通知 ID，零 ID 不能记成已发送。按[微软通知接入说明](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/app-notifications-dotnet)补齐 MSIX 的通知激活与 COM 声明、注册、主窗口激活和退出释放。早期发送也先注册；配置暂时因恢复事务不可读时，只使用先前已观测的有效通知策略，不猜测用户是否授权通知。

| 用户级别 | 策略 |
| --- | --- |
| 关闭 | 所有系统通知均抑制 |
| 仅重要 | 内核异常退出、已使用的透明服务失效、代理应用失败、数据恢复要求等可用性故障 |
| 默认 | 另含模式变更、可用性恢复、新版本、操作失败和测试超时 |
| 详细 | 再含导入、更新、保存、切换、检查、测速、清理等成功结果 |

用户主动取消、被跳过的后台更新、空操作、页面载入后的持续采样和列表流不会作为成功或失败反复弹出通知。一次连接测试中的多个超时合并发送，内容使用目标标签，不带完整 URL、订阅令牌或原始异常文本。

| 操作或事件 | 通知入口与处理 |
| --- | --- |
| 本地配置导入、订阅导入与更新、校验、启用、重命名、删除、历史恢复 | 当前数据代的目录入口报告实际提交结果，覆盖 UI 与使用同一端口的 Agent 操作 |
| 订阅自动更新 | 调度器适配器报告完成或失败；过期、停用和取消的更新保持安静 |
| 节点选择、Provider 更新、节点测速 | 使用同一操作通知边界；部分节点未返回延迟时报告需要关注的结果 |
| 连接关闭、全部断开 | 控制请求完成后报告结果；连接流与周期刷新保持安静 |
| 日志按日期、容量、条数、筛选清理及全部清理 | 清理完成后报告，预览不通知 |
| 设置保存、分组和全部重置、失败后的显式重试 | 等待完整操作及恢复判断，不把仅保存待应用值等同于成功 |
| 数据包导入与各类导出 | 完成提交或文件关闭后报告；需要恢复的事务按重要级别处理 |
| Windows 原生诊断、应用修正、还原修正 | 按实际健康结果区分成功与需要处理的结果 |
| 设置页连接测试、主页网站测试与公网信息查询 | 覆盖成功、HTTP 失败和超时；路线已改变而丢弃的旧结果不通知 |
| 主页和关于页检查更新 | 详细级别报告检查结果，新版本另按默认级别提示 |
| 触发器创建、修改、开关、排序、删除 | 持久化成功才报告；执行通知继续遵循原触发器开关和幂等 outbox |
| MCP 应用设置、关闭、重置、轮换、复制 | 使用真实运行状态；复制反馈不包含凭据；端口输入校验留在页内 |
| 启动健康检查 | 详细级别报告完成，需要处理的非可选项目按默认级别提示 |
| 模式控制、内核退出、透明服务失效与恢复 | 保留模式通知，增加可用性故障和恢复通知，状态不变时不重复报告 |
| 未预期的异步操作错误 | 由应用错误边界提供普通错误通知，已有明确通知的边界避免再次发送 |

补充了各级别、总开关、提交后才通知、取消与空结果静默、部分失败、通知传输故障不改变业务结果、注册释放，以及恢复期间策略读取等行为回归。页面反馈继续保留，通知传输失败不能使已提交的导入或设置回滚。
