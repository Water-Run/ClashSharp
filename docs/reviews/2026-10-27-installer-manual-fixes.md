# 安装器手验问题 1、2

用户开始逐部分手验后指出：下载 ZIP 解压应在第一层直接看到 `Setup.exe`；安装器详情中的滚动条压住右侧状态文字，多行“已就绪”重复。

## 修改

- 正式安装入口统一为 `Setup.exe`，同步修改构建输出、校验和文件名、候选身份、载荷审计及提权文件名约束。旧安装入口和开发文件名不能作为新候选的提权入口。
- 用户进一步指定发行文件名为 `Clash#.zip`。根目录文件只有 `Setup.exe`、`LICENSE`、`README.md`，其余分别放入 `payload`、`licenses`、`metadata` 子目录，不增加 `release` 外层。独立审计器仍在私有工作目录中分离身份文件与十项发行文件，严格库存和摘要约束保持。
- 随包 README 单独编写，包含简中、英文、繁中、韩文、俄文和波斯文的简明安装说明与各语言完整文档链接。LICENSE 保留仓库许可原文；两份文档一并绑定候选摘要。
- 主滚动内容右侧预留 24 DIP，Fluent 原生滚动条与正文、状态文字保持分离。详情中隐藏逐行重复的成功状态，失败项仍显示“未就绪”及其原有说明。
- 现有归档检查增加普通 ZIP 解压后的根目录入口、相邻载荷及准确字节校验；实际 WPF 行为检查增加默认／最小窗口的滚动条与内容几何间隔、成功状态隐藏和失败状态保留。

## 验证状态

首批源码 `50ed7a8` 的服务器五项 PowerShell 契约、PS7／5.1 语法、42 项定向测试及全解决方案格式检查通过；包含真实 WPF 的默认／最小窗口滚动条几何与成功／失败状态检查。随后按用户补充要求收拢根目录、加入许可和多语言简明文档，需接续验证该包装修订、准确提交 CI、新内部签名候选和实际解压入口。旧候选的检查结果不作为新候选通过依据。服务器保持首次安装手验状态，原数据备份与隔离保留，不替用户点击安装。
