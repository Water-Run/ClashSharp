# 弹窗按屏幕工作区定尺寸（2026-11-15）

## 问题与实现

用户在试装时指出，启动检查等弹窗不应被背后的主窗口大小框住。原实现把 ContentDialog 放在主窗口的 XamlRoot 内，并且多处内容宽高直接按主窗口计算；主窗口较小时会压缩弹窗和内部列表。

所有经共用协调器显示的 ContentDialog 现使用独立的原生模态宿主。AppWindow 在创建时指定 owner；DesktopWindowXamlSource 提供独立 XAML 根。主窗口只负责归属和初始居中，不再决定弹窗宽高。窗口和内容上限按所在显示器工作区、DPI 计算，保留原有 ContentDialog 的按钮、验证、取消与焦点处理。内容原有的首选阅读宽度保持不变，不把短对话框无条件拉满屏幕。

调用端使用 OwnerXamlRoot 传递归属，控件通过宿主的视觉树取得真正的 XamlRoot。没有在两个 XAML 根之间强行重设控件的根，也没有运行时修改原生 HWND owner。屏幕布局同时覆盖启动检查、冲突检查、设置选择器、磁贴编辑、订阅编辑和数据导入导出等共用路径。

关闭时释放 XAML island 和原生窗口，恢复 owner；父窗口销毁通过独立的 owner lifetime 取消 WinRT 展示任务，避免等待已失去原生窗口的隐藏动画。模态窗口的主题、语言、方向和前台通知抑制继续跟随应用。

- 弹窗、资源及架构的本地定向回归 338 项通过，零失败、零跳过。锁定还原与 Release 全解决方案构建通过，零警告、零错误；最终提交的完整 CI 和签名包在收尾时记录。
