官方 SDK 2.2.0 客户端与独立只读服务探针均在服务器编译。原数据拒绝用例确认在剪贴板/SDK 或服务关联加载前停止。服务探针复用准确生产版本的严格关联读取、关联派生管道名、连接后 SCM 服务器 PID 认证与版本化帧校验，只允许 Hello/Status，不允许 Start/Stop/Reload。

第一轮从 SSH 网络登录上下文直接执行探针，服务管道访问被拒绝，记录 UnauthorizedAccessException。阶段在终止任何内核或放行数据包之前停止；SDK 按其 finally 正常关闭 TUN，五条本次管理路由撤销，独立任务仅观察清理完成。该轮保留为拒绝，未记自动重启通过，也未放宽生产管道权限。

后续将相同只读探针放在原 SID 的交互式任务中，由受限目录的 Status 请求/结果队列传递观察。交互式任务先确认会话和非网络登录上下文，服务认证成功，再以新的 `single-r2` 阶段身份执行，没有覆盖或重放拒绝轮次。SDK 版本和阶段编译身份分别保留。

每个成功阶段先启动独立限时清理，绑定准确服务/应用 PID、启动时刻、摘要和临时数据代；为当时五个 SSH/RDP 管理地址记录原出口并建立仅本轮所有的 ActiveStore 主机路由。只有认证服务快照、LocalSystem 服务子进程父子关系/摘要、实际产品 TUN `/0` 选路及管理出口都通过后，才放行数据请求或精确终止子进程。

## 两个实际阶段

| 阶段 | 实际观察 |
| --- | --- |
| 单次异常退出 | 真实 TUN 先转发 131,072 字节，精确终止服务子进程，新的 PID 恢复 Running。服务会话、活动运行代、数据代和配置 SHA-256 与原快照一致，再次实际转发同样数据。 |
| 有限自动重启 | 连续终止当前服务子进程三次，每次均独立确认新 PID、同一不可变运行代和实际 TUN 转发。进程创建时间与终止记录观察到约 0.257、1.007、3.007 秒间隔，与默认 250 毫秒/1 秒/3 秒退避相符；不以墙钟精确相等作为通过条件。 |
| 预算耗尽 | 第四次终止后，认证快照为 Faulted、`service.child.restart_exhausted`、无子 PID，仍保留原会话/运行代/数据代/配置摘要。随后五秒重复观察，未重新创建内核。 |
| 显式恢复与预算重建 | SDK 以新操作标识重新请求 RuleTakeover，服务宿主没有重启，实际内核恢复。新显式请求可建立新的运行代，但数据代保持。再次终止后又自动重启，并验证真实数据转发，证明预算重新生效。 |
| 正常结束 | 两阶段都由原有关闭代理事务结束，SDK 确认已知 Disabled、无内核/TUN/系统代理，所有本次主机路由撤销，原路由表及原网卡 DNS 与基线一致。独立清理均未执行到时兜底或 SCM 强停。 |

单次阶段两次、预算阶段六次，共八次，每次 **131,072 字节**，均逐字节一致，SHA-256 为 `FEB1E4409D009E0EC502EAABE321F86B5197A881E9B765252EC8A75D6957596D`。HTTP 客户端明确不使用显式代理，通过 TUN 到本次独占的回环 HTTP 上游；只有文档测试地址匹配合成代理规则，其余 DIRECT。没有用原订阅、商业节点或受限网站可达性作为断言。

六次内核终止是精确注入的异常，退出码均为 -1，不能称为正常内核退出。服务宿主与应用在这些终止期间持续保留，未将重新启动整个宿主替代子进程重启。
