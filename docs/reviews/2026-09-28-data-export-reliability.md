# 备份导出可靠性（2026-09-28）

检查生产设置与数据恢复入口时发现两处缺口。设置页与磁贴共用的导出入口没有取得设置、配置写入所用的操作许可，读取偏好和逐个配置文件时可能与已经开始的更新交错。日志导出则先删除目标数据库及其 WAL/SHM 文件，再调用 SQLite 备份；源数据库损坏时，已有备份会变为空文件。

新增 `SettingsExportCoordinator` 并在主程序装配，设置页和磁贴通过原有共用入口调用。文件选择器结束后才排空现有修改，并持有独占许可直到 XML 或 SQLite 导出实际完成；等待时取消不会进入写入，已经运行的写入不会因页面取消而提前释放许可。该操作不停止代理内核。此修复没有启用第二套偏好存储，完整 JSON 权威与代际容器切换仍未完成。

日志导出继续使用 [Microsoft.Data.Sqlite 的在线备份 API](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/backup)，先写同目录临时数据库，切换为 DELETE 日志模式并通过 `quick_check`，关闭连接后才替换目标。旧备份保留到完整快照发布；写入、校验或替换失败时清理本次临时文件。拒绝导出到活动数据库及其 WAL、SHM、journal 路径，也不删除目标现有的恢复文件。[SQLite WAL 文档](https://www.sqlite.org/wal.html)说明这些文件与数据库恢复有关，不能当作无用附件清理。
