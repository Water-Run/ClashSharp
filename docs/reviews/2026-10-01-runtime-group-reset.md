# 运行时设置分组重置检查点

此检查点基于私有提交 `9005668c86debbe6f3e103451519a9fb481dbdc0`。启动、代理和 TUN 的分组重置现在通过 `ISettingsRuntimeGroupReset` 使用当前数据目录中的统一设置服务。整个命令持有修改许可和数据目录租约，默认值来自设置注册表；不支持 TUN 时采用关闭状态。只重置所选组的期望值，不替换数据目录，不恢复旧设置写入。

分组重置采用新设置模型的“期望值与已验证效果”语义：保存成功但应用失败时，保留期望值和失败批次，页面显示尚未生效并提供明确的重试按钮。页面区分保存和生效状态，重置通过统一设置服务完成；再次点击重置不会静默重放失败的操作。重试前同时核对数据目录、批次、尝试身份及条目修订/摘要；请求过期时停止并提示重新检查当前值。无关设置的失败批次保持原身份和状态。

重试的第一个持久决定一旦确认，后续参与者和保存继续由原命令负责，页面取消不会遗弃它们。此前同时存在多个失败批次时，底层拒绝直接开始旧尝试会让页面漏掉重试入口；新增回归复现并修复了这一分类错误，保留原失败身份，仍要求用户明确重试。

页面只在完整操作返回后公布整组字段。应用失败时也能显示已保存的期望值，但不会把它们登记为已验证效果。成功导入或全量重置清除旧重试入口。订阅者通知出错不会遮蔽已经验证的业务结果：保留通知异常并显示重启状态，进程级标记不会被随后加载的普通页面清除。提示和按钮文本补齐八种语言，使用现有 WinUI `InfoBar` 和按钮。

`SettingsRuntimeMutationAdapter` 中旧导入、重置收据和同步设置写入代码已删除；它不再依赖旧数据包服务、旧设置实例或网络重置收据。生产设置页必须注入新的分组重置服务；旧视图模型测试兼容路径没有被用作生产回退。
