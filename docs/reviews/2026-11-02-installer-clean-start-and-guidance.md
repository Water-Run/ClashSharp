# 安装器干净环境启动与错误指引

用户清理蓝机后，从唯一保留的完整压缩包解压并启动 Setup.exe，出现“无法检查安装状态”、版本“—”及与当前失败无关的账户操作。原包摘要与文件签名身份未改变；旧安装器的诊断为 `installer.elevation.authenticode_invalid`，Windows 对临时内部签名返回未受信任状态，系统中已无该产品的临时根证书。

此前验收预先借用了内部 Authenticode 根信任，没有覆盖清除这份信任后的首次启动。本轮修复这一验收遗漏，并保持用户要求的最终形态：蓝机未安装，仅保留一个完整 ZIP，Setup.exe 在第一层。

## 修复内容

内部候选增加明确的编译配置，受签名生产安装器配置约束，由内部候选构建器显式启用，并在版本行显示“内部测试版”。Windows 验签继续检查 PE 文件摘要和实际签名；只有系统缺少根信任这一特定结果，才允许进一步核验短期内部自签证书的身份、用途及内存链。外层验证器仍须匹配嵌入清单中固定的签名指纹，并保持原文件锁与文件身份核对，才授予执行租约。这条路径不写入系统证书存储。

默认正式签名配置继续要求 Windows 系统信任。错误签名身份、文件修改、任意自签发布者和其他验签失败均拒绝；没有增加可由命令行、设置文件或环境变量在运行时切换的宽松模式。构建配置检查覆盖预览、开发、正式签名及内部候选，并拒绝不完整的内部配置。

版本号从当前可执行文件的嵌入清单传入显示模型，在检查开始前和失败后都显示“安装包版本”，不依赖安装状态读取成功。签名无效、不受信任、过期、撤销、缺少签名、缺少文件及文件摘要不匹配有明确原因和对应下一步；诊断代码继续可选取，不暴露异常原文、私有路径或凭据。

启动校验失败时隐藏账户切换和旧账户副本操作。另一个 Windows 账户的受保护安装记录不可读时，保留独立认证的账户恢复入口，并显示相应账户提示，维持既有迁移和显式确认语义。

## 当前验证

- 新增六项启动提示回归在旧实现上全部失败，修正后通过。
- 展示层完整 222 项通过，覆盖检查失败前后的版本显示、账户操作隐藏、恢复检查以及既有账户迁移和卸载确认。
- 实际 Windows 验签定向 19 项通过：包含无预装根的内部包、正式模式仍拒绝、错误固定身份、篡改 PE 文件及任意其他自签发布者拒绝；测试不安装根证书。
- 构建配置检查为四种有效配置及五种无效组合，内部候选控制器的 52 项合约检查通过。
- 19 项目 Release/x64 构建零警告、零错误，锁定还原和定向格式复核通过。蓝机直接对原实际签名执行只读探针：内部策略接受、正式策略拒绝、根存储逐项不变，未执行原安装器或导入信任。

第一次展示层完整运行暴露了账户入口可独立处理其他用户不可读安装记录的既有契约；已保留这一专属恢复情况，最终 222 项完整通过。原失败报告保留在忽略的 `artifacts/verification/installer-clean-start-20261102/`，不覆盖为通过记录。

同一源码的完整 CI、内部签名候选及蓝机无临时 Auth 根的首次界面／安装／卸载验收随后绑定并追加。Windows 信任结果遵循[WinVerifyTrust](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/nf-wintrust-winverifytrust)；内部候选的明确锚定证书仅用于[内存自定义根链](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.x509certificates.x509chaintrustmode)，正式配置的系统信任策略不变。
