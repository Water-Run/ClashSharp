# 网络维护记录与数据目录身份检查点

此检查点基于私有提交 `d7808982319727a29e5cdee4e564268d89c02121`。原网络维护和退出恢复记录不包含数据目录身份，恢复步骤又先于当前数据目录的打开；导入、重置和后续启动不能仅凭相同的模式、端口或网络状态判断记录属于当前目录。

网络记录升级到 schema 2，携带当前数据目录 GUID；管理目录的基线和目标摘要也包含该身份。旧 schema 1 记录仍可在旧存储阶段恢复，但不能在管理目录已绑定后使用。空 GUID、旧版本混入管理目录身份和不支持的版本会被拒绝。计划创建、恢复、校验、应用、探测、补偿、激活和清理，以及设置提交者均核对当前绑定身份。绑定后的目录不可用时不会降级成旧存储。管理目录的模式修改也不能返回旧的同步设置写入路径。

新增启动阶段 `recovery-data-generation`，顺序为 142，在凭据初始化之后、网络清理所有权登记和日志恢复之前。已经存在管理目录时，只打开并绑定该目录、登记资源所有者，保持外观设置、网络、采样和触发器尚未启动；网络恢复及登录恢复助手随后读取这份数据。不存在管理目录时，不进行首次迁移，仍先处理旧日志，再由第 225 阶段迁移。读取存储可能创建必要的锁目录，这不等于创建新的数据代际或发布当前指针。

`OpenExistingAdmittedAsync` 在打开前后核对预期指针，指针丢失或发生改变时拒绝继续，不分配新目录、不悄悄改用另一代。即使指针缺失，也会检查未完成的数据替换记录；因此登录恢复助手不能绕过这一恢复要求。恢复日志输出改用当前日志端口。
