# 设置背景与原生颜色标签的语言刷新

`149b756` 的实图发现两处遗漏：设置页的文字刷新排在模态操作之后，弹窗打开时背景仍显示旧语言；颜色选择器的通道标签在创建模板时赋值，此后不会随应用目录重新翻译。

设置页现在立即在输入绑定保护下更新文字与稳定选项。语言通知可能处于外观事务内部，因此这条路径仅使用已展示的值；另外派发的提交通知才读取新偏好，并沿用保护在途网络、采样和启动选择的投影逻辑。MCP 状态读取仍排队，但已有状态和权限草稿的文字立即刷新，不增加读取或变更授权。恢复行保留原对象、快照和批次，只更新标题及重试文字。

颜色选择器继续使用原生 WinUI 控件及模板，在已存在的命名部件上更新 RGB/HSV 通道文字与无障碍名称，不重新创建输入框或改写颜色值。应用目录补充八种语言的通道、模式、十六进制值及键盘说明。实现对照了所固定 WinUI 1.8 系列的 [ColorPicker 模板初始化](https://github.com/microsoft/microsoft-ui-xaml/blob/ba3b6cd989b4bac7c82791ad76a28d837bbf903b/src/controls/dev/ColorPicker/ColorPicker.cpp)；模板内部标签的生命周期也是本次遗漏的原因。

服务器节点为 `dialog-language-details-20261020`，已核对 1,916 个输入文件；完整构建零警告、零错误，修改文件的产品与测试格式检查通过，相关 **382 项通过、零失败/跳过**。新增回归覆盖：读取进行中立即翻译并保留 MCP 草稿；网络申请进行中保留端口草稿且不重放；仅翻译恢复提示时保留原行、快照、批次及错误。

准确提交的完整 CI、签名、安装及原生 RGB/HSV 与背景语言复验继续。当前安装仍为 `149b756`，最新原数据为 `dialog-live-presentation-20261020/after-native-review` 的 46 文件、8 份历史。本轮未在本机运行产品或 Sandbox，尚不计整体视觉通过。
