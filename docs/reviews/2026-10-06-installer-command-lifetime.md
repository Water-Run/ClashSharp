# 安装器异步命令的任务持有

准确 `908947b` 的内部 `1.0.0.0` 候选在 Server 2025 Desktop 完成同版本内容冲突拒绝：原服务 PID、配置和权限、七个机器文件、39 个用户文件、证书与代理均保持，12 项独立核对通过。随后正常卸载旧候选并安装新候选，暴露了安装期间的等待问题。

## 原生观察与修正

Windows AppX 日志在 03:10:57 UTC 确认新包部署成功，安装的主程序集 SHA-256 为 `CA44CDFA9E734F0AC0F9F68ABAC42D7A6EC9609F442F479DCF8043C522007DAC`，与候选 MSIX 内文件相同。但安装器仍显示 46% 的应用安装阶段，事务停留在 `MachineReserved` 第 2 代，尚未安装服务。

保留该事务并检查进程。父进程 UI 调度线程正常等待消息；托管堆中的 ViewModel 仍有执行中标记和取消源，但已经没有对应的异步状态机执行链。helper 随后退出。诊断只在服务器保存，私有转储未下载或纳入发行材料。

`AsyncDelegateCommand` 原来只保存执行中的整数标记，调用者放弃返回任务后，命令自身没有强引用持有正在等待的执行任务。新增回归使用仅保留弱完成句柄的来源，在等待期间执行 GC：成功与失败两种情况均复现执行对象被回收。命令现在持续持有任务，直到完成处理进入 `finally` 后释放，再恢复可执行状态。

修正前定向测试 3 项通过、2 项失败；修正后完整安装器展示层 184 项全部通过，无失败或跳过。两项新增测试也确认成功及失败结束后释放执行对象。相关 C# 文件的格式检查通过，18 项目 Release/x64 构建零警告、零错误。当前修正仍需重新构建安装器，并在原载荷和保留的安装事务上完成原生恢复验证；本记录不提前宣称等待问题已经获得实机修复证明。

## 验收前提与清理

旧的 Windows 11 Sandbox 场景只部署 MSIX，没有安装器建立的服务关联。当前候选在首次数据初始化前报告 `service.provisioning.association_missing`，其权限检查按既有契约拒绝继续。失败记录和客体/宿主清理收据已保留，不能计为完整安装后的启动通过。代际日志读取与完整安装前提的验收改进仍在进行。

用户要求清理服务器开发残留后，核对发现旧 `bin/obj` 已清空，主要残留为历史验收打包输出。清理了 107 个已完成候选的 `source/artifacts/installer` 或 `source-archive/artifacts/installer` 目录，保留小型清单、日志、摘要及证书材料。目标逐一通过绝对路径范围与 reparse 检查，当前候选、回退候选、有效签名归属、固定输入和用户备份均不在删除范围。

移除的生成产物约 32 GiB；清理后 C 盘可用空间约 107 GiB。再次核对当前和回退安装器摘要及 39 份备份文件全部一致，安装事务保持。原始清理收据位于 `artifacts/verification/server-cleanup-20261006/`；安装观察和测试记录位于 `artifacts/verification/tcp-runtime-20261006/`。
