# 服务重试耗尽后的归属与恢复

准确 `9a959da` 内部 `1.0.0.0` 候选在 Server 2025 Desktop 的活动 TUN 下完成四次定点核心中断，证明三次自动重试有界。原生验收随后发现：耗尽后重选原模式和正常退出均被归属预检查拒绝。修正实现和回归已完成，完整回归与新候选原生复验继续推进。

## 原生故障证据

本机内网地址不可达时，改用已有公网 SSH 别名；连接前核对保存的主机密钥与内网别名一致，连接后核对计算机名与实际程序集摘要。既有验收账户和远程桌面保持。产品正常关闭时保存并核验 158 个文件，代理仍为原始摘要。

活动规则接管启用 TUN，服务 26604 拥有会话 0 核心 3476，Meta 网卡 Up、九条接口路由。独立 HTTP 探针禁用代理，核对所选路由属于 Meta，返回 200、预期正文且接口收发增长。

只读服务探针链接准确候选的关联读取器、命名管道客户端、SCM 管道身份校验器及 Core 协议程序集，运行在普通验收账户。它只发送 Hello/Status、核对同一服务会话，并筛选输出版本、生命周期、生成代摘要和稳定故障码；关联凭据不写入报告。首次观察为 Running、运行配置第 16 代，当前用户数据第 5 代。

11:55 UTC，核对服务 PID/创建时间/文件摘要及子进程会话/父进程/文件摘要后，依次结束 3476、26416、23860、19044。前三次自动恢复的等待分别对应 250 ms、1 s、3 s 的既有退避；每次恢复通过认证的状态读取确认 Running、同一服务会话、相同配置代与摘要。第四次后服务为 Faulted、ChildProcessId=null，明确报告 `service.child.restart_exhausted`。应用和看门狗保持，TUN、接口路由与监听清空，系统代理保持基线。

控制页正确显示不可用。但点击已选规则模式后出现应用失败与设置未生效提示：31 项设置中 27 已验证、4 未验证，待处理操作 1。随后正常退出也显示“未能安全退出”，应用保留并允许重试。这些失败状态及截图均保留。

人工确认准确服务身份后停止服务，产品出口再次重试才完成退出；再人工恢复服务 Auto/Running，新 PID 23716。超时保护未运行并已撤销。这是测试环境恢复，不作为产品自动恢复或正常退出通过。另存并核验 156 个故障后文件，保留第 5 代和待处理操作，供新候选接续验收。

18 份筛选收据归档 SHA-256 为 `DFCCCDEE497A6274B8E4BA39BDA02715F3FF6076439D9FB5AC16489CDB418E4B`，位于 `artifacts/verification/service-login-native-20261006/`。用户配置、原始日志、服务凭据与完整备份没有下载。

## 修正边界

服务监督器仅在已退出 Job 的停止与释放确认完成、当前进程引用清空后耗尽重试。清理失败返回独立故障码并保留归属，不会进入重试耗尽终态。故障终态保留的生成代和摘要描述目标配置，不能因此推定仍有运行核心。

客户端原来的释放判定只接受 SCM 已停止或认证的空白 Stopped 快照，现在增加认证且结构完整的重试耗尽终态：服务仍部署、当前协议与非空会话、无运行核心/子进程、明确耗尽码、无清理/关联故障、正生成代及规范配置摘要。旧根目录允许空数据代，显式空 GUID 被拒绝。其他 Faulted、Starting、未知或矛盾状态仍不证明释放。

该判定让原有只读观察识别已释放的非活动基线，重试继续通过现有设置权威事务、完整网络配置与独立结果验证；退出继续通过现有维护协议。没有修改重试次数，也没有把故障显示成健康运行。

四项新增回归先在旧实现上全部失败。修正后相关 119 项通过；新增二项耗尽证明、15 项拒绝反例、三项真实运行配置观察/接管/禁用回归，共 20 项。既有监督器预算测试补充确认三个 Job 包装均已释放。最终主程序 4,002 项全部通过、零失败和零跳过，18 项目 Release/x64 构建零警告/错误，格式检查通过。

服务宿主崩溃、登录恢复、其余退出补偿失败和平台矩阵仍待验；正式签名后续配置，版本保持 `1.0.0.0`。
