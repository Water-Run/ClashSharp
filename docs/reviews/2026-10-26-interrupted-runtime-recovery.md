# 退出中断后的后台任务与 MCP 恢复

深入检查主程序生命周期时，发现部分后台任务已经开始停止、但等待被取消或超时后，没有进入退出失败的恢复清单。退出返回失败、应用继续运行时，订阅更新或采样可能不再调度；MCP 也可能保持撤下访问权限的状态。

## 复现与修正

在准确基线 `1c177e9` 上，使用真实 `RuntimeLifecycleCoordinator`、`SupervisedLoop` 和控制的异步任务复现三种情况：用户取消、等待超时，以及后台工作无法在恢复期限内结束。三个用例均发现受影响任务没有收到恢复调用。MCP 使用真实控制器配合模拟监听器，停止失败和用户取消两个用例均复现原凭据不能再次认证。

新增 `RuntimeQuiescenceException`，在已经开始暂停的操作失败时携带原始失败和准确的恢复状态。生命周期会把当前任务与先前暂停的任务一起逆序恢复，再按原始异常区分取消、超时和普通失败。恢复失败会报告具体任务，继续恢复更早的任务，不把部分恢复当作全部恢复成功。

订阅及采样所用的监督循环、MCP 参与者接入这一交接。触发器已有自己的中断恢复；若自身恢复再次失败，也保留恢复状态和两个原始失败。严重异常仍按原策略传播。MCP 恢复使用既有配置、端口、凭据和权限，不重新生成凭据或扩大授权。

数据代适配器对中断状态执行与正常状态相同的绑定：只允许交回原参与者、原数据代，成功恢复后不能重放。新增用例同时检查原始内部状态不能直接绕过适配器、数据代替换后拒绝旧恢复状态。
