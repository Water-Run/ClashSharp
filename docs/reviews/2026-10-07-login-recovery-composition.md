# 登录代理恢复的无界面依赖修复

真实 Windows 登录已经触发 `1.0.0.0` 的代理恢复助手，但准确 `a09d31d` 候选没有恢复遗留系统代理。失败定位于恢复数据代的依赖装配：助手不创建窗口，工厂却无条件要求启动窗口，因而在恢复步骤执行前退出。本记录区分实际失败、手工网络恢复、代码验证和待进行的修复候选实机复验。

## 原始失败

Server 2025 Desktop 的验收账户先通过产品启用登录代理恢复，Windows 注册状态为 Enabled；普通应用登录启动保持 Disabled。切换到应用拥有的系统代理后，实际转发返回 200 和预期正文，31 项设置已验证、待处理为零。

2026-10-06 15:35:43 UTC，核对 PID、创建时间、文件摘要和父子关系后，先结束看门狗 11568，再结束应用 5648。Job 清理核心 13988，保留真实代理所有权日志及租约，代理仍指向失去监听的应用端口。随后注销会话 7 并重新登录已有验收账户，会话变为 8。未重新初始化凭据。

Windows 在 15:44:00 UTC 启动助手 11404，正确账户、会话、打包可执行文件和 `--restore-proxy-on-startup` 参数均被观察到，主窗口句柄为零。100 秒观察截止时代理没有恢复；诊断性的直接助手请求同样失败。助手进程退出码 0 不是恢复成功的证据。

两次启动的本地文本回退诊断均在 `recovery-data-generation` 处抛出 `InvalidOperationException`，准确消息为 `The generation startup window is unavailable.`。只导出该已知消息的匹配结果和 SHA-256，不导出完整日志。该消息的 SHA-256 为 `E938DE1C46AF114B01CA6595851053DAC5CA7298C0BE08FB85B2F9028F313A80`。

原超时保护因只读注册表句柄退出失败。修正验收脚本为显式可写句柄后，仅按真实所有权日志恢复四个原始代理字段；第五个 AutoDetect 字段不改动。15:51 UTC 原代理指纹恢复为 `C4CB7760F87D6A3AD3C80022F6747BBD78F8383916AA2476C087206C1ABEDC64`。此操作属于手工测试收尾，不计为产品恢复通过。旧日志和租约保留诊断，三项自有测试任务已撤销。

原失败的 16 份筛选 JSON 收据归档 SHA-256 为 `264346D93AFF3745C3E824F9B64C835F8C1CA8994047B75CDDB3FAD565264750`。更新前另存并逐文件验证 160 个闭合用户文件；完整备份留在服务器私有目录。

## 代码修复和验证

数据代工厂改为按助手启动标志选择界面依赖。恢复路径不解析窗口，仍构造完整、未激活的设置参与者及仓库；无窗口的外观操作和调度请求明确失败，不能伪造外观应用成功。普通路径继续要求真实窗口，并保留窗口调度和退出状态。组合根使用实际进程退出请求通道读取退出状态，注入给业务组件的接口保持一致。

新增五项界面边界测试和一项真实仓库/运行时组合测试。原行为下两项测试失败、一项普通窗口缺席检查通过；修复后相关集 46 项通过。仓库集验证当前指针和完整设置信封逐字节保持，读取的是已有数据代的端口与模式，采样和触发器执行没有启动。初次集成测试错误地期待迁移后没有待处理设置，已改为比较原信封，原 45 通过/1 失败报告保留。

格式检查通过，主程序全量 4,008 项通过、失败与跳过为零；18 项目 Release 构建为零警告、零错误。一轮本地构建与仍运行的测试进程争用程序集文件，失败原因单独记录；等测试结束后的顺序构建通过。新的 `1.0.0.0` 内部候选原生复验继续进行。

## 未闭合范围

修复候选尚需完成真实注销/登录、独立代理指纹和日志清理核验、普通应用重开及正常退出。本节点不宣称登录恢复通过，也不宣称提前启动失败、全部退出补偿、Windows 11 完整安装器矩阵或正式发行完成。正式签名仍按用户选择留待后续配置。
