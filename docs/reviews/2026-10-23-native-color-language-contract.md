# 原生色板语言行为核对

本轮重新核对10月21日留下的“色板帮助缓存旧语言”结论。旧观察器只保存 `nativeSpectrumHelpMatchesRequested=false`，比较对象是应用自定义短句，并未保存原生帮助的实际文字。因此该结果不能证明原生帮助停留在旧语言；历史记录保留，当前结论以下面的直接证据为准。

复用已验收的3fe2413签名包及CI运行39931278275（**7,247 / 0 / 0**），在服务器隔离数据中读取真实UIA属性。另从实际加载的框架PRI导出并匹配语言限定资源，绑定DLL和PRI摘要。当前实际框架为 `Microsoft.WindowsAppRuntime.1.8_8000.994.2142.0`，WinUI DLL版本 `3.1.8.2503`，源码标识 `c03f50c96989525a1487cf9404f2306b314a23d0`；不把项目所声明的最低框架版本误写为实际加载版本。

同一RGB草稿保持黄色，三个语言下的原生帮助、控件类型及HSV数值模板都与实际框架资源匹配：

| 语言 | 实际原生帮助 | 原生控件类型 |
|---|---|---|
| 中文 | 带有箭头键的 2D 导航 | 2D 滑块 |
| 德语 | 2D-Navigation mit Pfeiltasten | 2D-Schieberegler |
| 波斯语 | پیمایش ۲ بعدی با کلیدهای پیکان | لغزنده ۲ بعدی |

值字符串中的颜色名称有不同生命周期：暖进程从中文切到德语、波斯语后仍以“黄色”开头，而后面的HSV文字已更新。明确取消草稿并正常退出后，保留波斯语设置重新启动，同样黄色值改为“زرد”。RGB→HSV只切换模式、没有重写通道输入，仍保持255/255/0、60/100/100及#FFFF00；色谱顶部、RGB字段与HSV字段的三张可见窗口图已检查，滚动区域和底部操作正常。

这一行为与实际框架的[原生资源载入实现](https://github.com/microsoft/microsoft-ui-xaml/blob/c03f50c96989525a1487cf9404f2306b314a23d0/dxaml/xcp/host/win/desktop/BrowserHost.cpp#L24-L55)相符：颜色名称所用的MUI库在进程中首次加载后保留。应用不操作框架私有资源句柄，也不替换原生色板或其自动化提供方。

源码清理移除了不会被原生色板帮助提供方采用的 `AutomationProperties.HelpText` 覆盖及八语言未使用短句。八种语言的设置说明现在明确：应用文字立即更新，颜色名称等部分系统文字会在下次启动后更新。这是对已验证生命周期的说明，不宣称颜色名称已经可以在原进程即时切换。

服务器核对1,660个既有构建相关输入后应用九文件修订，修改文件格式检查、完整Release/x64构建零警告／错误，相关 **678 / 0 / 0** 通过。本机未运行产品或Sandbox。准确CI及新说明的候选界面复验接续；整体Windows 11和剩余显示／恢复验收未完成。
