# 启动错误窗口显示前恢复代理

准确 `63fa907` 的普通启动错误窗口已经通过关闭后的收尾，但窗口停留时仍保留已失去核心的系统代理。22:33:54 UTC 的实机收据明确记录代理启用、日志和租约保留，22:34:10 关闭后的收据才恢复基线。这个边界会让用户阅读错误期间的其他程序继续使用失效代理，需要在展示错误前完成安全收尾。

## 实现

普通启动 Fatal 和启动未完成的异常在显示错误前，先放弃延迟窗口完成，再停止并释放宿主，然后独立恢复日志证明的代理所有权。普通成功启动及运行后的生命周期异常仍沿用既有退出偏好。宿主已经跨过终结处置边界时记录原诊断，继续独立代理恢复，避免重入已处置服务。

准备过程不撤销看门狗、不清租约、不释放 Installer 或代理恢复锁；诊断窗口仍持有责任，最终关闭才正常退休。停止失败不抢先恢复尚未停下的运行时；代理恢复失败也保留责任并记录生命周期诊断，最终退出可以重试。恢复不依赖设置仓库，仍使用真实所有权日志，不猜测端口或认领外部代理。

新增四项回归使用实际代理合并、进程生命周期执行器与文件锁，覆盖异步宿主停止前不恢复、原始基线和外部状态保留、停止失败后的同一责任重试，以及恢复失败后不重复停止/处置已终结宿主。九项相关回归及主程序全量 4,027 项全部通过，零失败、零跳过；18 项目 Release 构建零警告、零错误，完整格式通过。准确新候选的 CI 和实机验收继续进行；不把旧候选的正常退出结果计为新行为通过。

## 原生验收边界

新候选需要复验错误窗口仍打开且数据指针仍被锁住时的完整代理基线，以及窗口责任、关闭后清理、外部状态与恢复失败后的退出重试。版本保持 `1.0.0.0`，签名沿用内部验收身份；G06、平台及发行矩阵仍未整体关闭。
