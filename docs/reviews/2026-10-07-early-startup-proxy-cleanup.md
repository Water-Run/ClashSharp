# 启动失败后独立收尾代理所有权

准确 `3eacf8f` 的 `1.0.0.0` 内部候选在数据指针不可读时，打包无窗口恢复助手返回启动 Fatal 并退出，但遗留的系统代理仍启用，代理日志和旧看门狗租约保留。网络清理注册位于数据恢复之后，早期失败没有进入该步骤；程序仍按正常退出撤销恢复责任，因此不能把宿主正常停止等同于代理已经恢复。

## 原生失败与恢复

先验证并保存闭合验收账户的 158 个文件。正常启动应用 12492、看门狗 24368、核心 20424，31 项设置全部验证，实际系统代理请求返回 200 和预期正文。核对 PID、创建时间、文件摘要和父子关系后，先结束看门狗再结束应用；核心随 Job 释放，保留真实代理日志。

Admin 测试进程用只读 FileStream、FileShare.None 独占现有 `current-generation.json`，不改变指针字节，不移动或修改数据目录。180 秒超时和提前释放信号均受控。18:11:15 UTC 请求准确打包无窗口助手。独立读取旧根的启动 SQLite 诊断确认 `recovery-data-generation` 返回 Fatal，稳定码 `data-generation.pointer_unavailable`，未执行后续网络清理注册及恢复步骤。

助手任务退出码为 0，但代理仍为 `57C439F4A2722C2A78B97C4BB195DB5FBB368BD9D9D90A45941D15809E52F75D`，无核心和监听，日志、租约仍在。保持该失败，不把任务退出码计为恢复通过。首次只读观察使用 Windows PowerShell 5.1 的 JSON 转义，代理摘要与统一 PowerShell 7 指纹不同；解除锁后的统一观察确认实际字段仍为遗留接管状态，旧文本回退文件也不是本次诊断来源。

提前释放指针锁，指针 SHA-256 保持 `43D584FFB0257A5AABC922DBAF1B806DFEAC48E5B362F6FA6160B5DFB6D67D89`。随后按真实日志显式手工恢复四个代理字段，AutoDetect 不变，原基线指纹恢复；超时保护未运行且已撤销。解除锁后的显式产品助手重试成功清除日志，此结果与失败期间恢复分开记录。31 项设置、第 5 代、11 个目录及修订号 245 保持。完整备份留在服务器私有目录。

15 份筛选 JSON 失败归档为 `568FCA3020D622F09006E02F4DF8FE399EA1985E89854B7B7607EAF0CC46F663`。只包含状态、摘要与稳定诊断，不包含完整日志、配置或密钥。

## 修复与验证

App 记录启动 Fatal 或启动未完成时的异常；已经进入 Running 后的生命周期异常不改变启动状态。宿主停止完成后、正常撤销看门狗和释放两项进程锁之前，失败启动必须独立恢复日志证明的 WinINet 所有权。这一路径不要求设置仓库成功打开，不能使用猜测端口的旧代理判断。正常成功启动继续采用已执行的退出偏好；成功登录助手也不覆盖用户关闭启动检查的设置。

恢复失败会保留进程锁和租约，允许既有有界退出流程重试或紧急 helper 接续；只有恢复成功才能正常撤销恢复责任。构造依赖不读取或修改注册表。五项回归使用实际代理合并及文件锁，覆盖原始基线、外部代理保留、正常策略不变、恢复失败后的同一责任重试，以及没有日志时不认领同端口外部代理。

五项针对性回归、主程序全量 4,023 项通过，失败与跳过为零；18 项目 Release 构建零警告、零错误，格式通过。一项导入排序检查失败后，仅格式化新增测试文件并重新验证，原检查结果保留。
