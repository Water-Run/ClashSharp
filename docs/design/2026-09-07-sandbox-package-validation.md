# Windows 11 Sandbox 包验证

本阶段把原有 Sandbox 占位脚本改为可执行的候选包安装与窗口启动检查。实际使用
Windows Sandbox 0.8.107.0、客体 Windows 11 build 26100，候选为 main 提交
`3282a03507f32c5c2e00824ee69ab7a1f5eee912` 的 CI 产物。

## 实际结果

- 断网客体启动探测成功，输入映射不可写，活动外部网卡为 0，客体机器标识与本机不同。
- `install-only` 完成依赖和 MSIX 安装、精确注册检查与测试资源清理。
- `launch-no-proxy` 确认实际进程包身份、已安装 EXE 摘要，以及持续 30 秒的主窗口；
  本次窗口观察耗时 30203 ms。测试随后终止自有进程并清理包与证书。
- 三次通过的客体运行均有单独主机收据：会话 ID 已消失、输入未变、本机代理摘要未变。
  第一次窗口运行观察 10122 ms，随后将默认观察时间延长为 30 秒并重新通过。
  当前报告门也要求至少 30 秒，因此早先 10 秒收据仅是历史验证，不满足当前窗口门槛。
- 102 项输入、报告及拒绝契约断言在 PowerShell 5.1 和 7 中通过。覆盖错误客体、
  包与运行标识、字符串被替换为数组、遗漏步骤、伪造时长、部分 JSON、载荷篡改、
  代理变化、缺少清理和未实现的场景。契约测试没有实际系统修改。
- 18 项目 Release x64 构建零警告、零错误；16 项仓库架构检查通过，format 检查
  1381 个文件零处变更。仓库检查曾发现新函数缺少帮助描述，补齐后通过。

## 发现的真实缺口

最初两次运行在应用包部署阶段失败，其余已创建资源仍完成清理。可复现错误为
`0x800B0109`：只向客体 CurrentUser/TrustedPeople 导入开发证书不能完成当前
完整 MSIX 的部署。改为客体 LocalMachine/TrustedPeople 后，同一候选包安装成功。
微软的 [MSIX 部署排错说明](https://learn.microsoft.com/en-us/windows/msix/msix-troubleshooting-guide)
也要求对这种自签名包检查机器 TrustedPeople 存储。

这项结果说明，现有安装器的用户证书导入与清理测试不构成完整部署成功证据。需要继续
明确正式签名与自签名开发发行的信任策略，在经过认证的机器执行范围内建立可恢复、
按精确证书归属清理的开发信任流程，并通过真实 WPF 安装矩阵验证。不能直接把用户
证书适配器改成机器证书适配器而沿用旧 SID 的授权及清理语义。

另外，客体中的 CIM 查询不可用；客体识别现使用注册表和固定路径。Sandbox CLI 的
connect 子进程会继承重定向输出管道；host 不再为该命令重定向输出，并限制其他
命令的进程和输出读取时间。测试结束后只停止本次保留的 Sandbox ID。

## 证据范围

本阶段是断网 MSIX 部署、窗口存在和自有测试资源清理。尚不证明完整 WinUI 页面
交互、正常退出、用户配置 GUI 导入、WPF 安装器卸载、应用数据彻底清除、代理接管后
崩溃恢复或正式签名发布。主窗口存在也不等同于所有启动步骤和页面功能正常。

`all`、`startup-with-proxy-config`、`cleanup-uninstall` 与真实代理可选场景继续明确
拒绝。版本仍为 1.0.0，生产安装执行门保持关闭。本机没有安装测试包、导入测试证书
或改变代理；真实系统修改只发生在已销毁的 Sandbox 客体内。
