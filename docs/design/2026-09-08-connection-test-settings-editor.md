# 连接测试地址的编辑与批量保存

设置页此前在对话框关闭后调用地址校验，却忽略失败结果；无效地址没有保存，但
用户也没有收到错误提示。同一个窗口还提供两个恢复默认入口，其中底部按钮立即
写入设置，编辑区按钮则只修改草稿，取消时的行为不一致。

三个地址原先分别调用存储属性写入。第一项写入后的观察者可以开始独占重置，
导致后两项被写入边界拒绝，留下只更新一部分的目标集合。

## 编辑交互

主按钮在关闭窗口前查询 ViewModel 的纯校验结果；无效输入取消关闭，在原窗口
显示本地化错误并聚焦第一个错误字段，保留全部草稿。三个输入框都有本地化的
无障碍名称。六个语言目录均包含新错误文案。

采用微软文档中的 [ContentDialog 主按钮校验与取消关闭](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.controls.contentdialog?view=windows-app-sdk-1.8)
语义。校验事件只读取输入，不写设置；对话框结束时解除事件，保存前再次检查
页面取消令牌，页面离开后不会应用迟到结果。

恢复默认只保留编辑区入口，使用 ViewModel 的默认地址填入草稿；点击保存才写入，
取消保持原值。保存、取消和恢复草稿因此具有一致的提交边界。

## 保存边界

`ISettingsStore` 将三个地址暴露为只读属性，并提供一个批量写入操作。
`AppSettingsStore` 将它转交现有 `AppSettingsService` authority；服务在一个普通
写入许可和同一锁内校验、暂存并提交三个值，全部提交后才发出变更通知。
独占重置不能在三个字段之间插入。ViewModel 在成功返回后更新显示值，重置地址
也使用这个批量接口。

这里复用既有的可回滚 LocalSettings 批量实现，没有新增影子存储，也没有将其
声称为可跨崩溃的文件代际提交。完整设置存储迁移仍由架构账本单独跟踪。

## 验证

- 新增 15 项回归：无效字段定位、草稿校验无写入、保存与重置失败时保留已提交
  显示值、三项共同提交后再通知，以及独占操作对完整批次的拒绝。
- 实际设置服务的通知回调在第一项通知中请求独占许可，确认全部通知看到已更新
  的三个地址，且独占许可要等本批次通知结束后才能取得。
- 完整 Release x64 solution 构建 0 警告、0 错误；主程序最终 TRX 为
  `1.0.0-m3d-main.trx`，2348 项通过、0 失败、0 跳过。最初的旧资源检查仍要求
  立即重置调用，已移除这一不再适用的断言；其余资源与行为测试保持。
- 完整 format 检查加载 1400 个文件、0 处变更。相关日志保存于忽略的
  `artifacts/verification` 目录。

这些结果验证源码、实际服务边界和编译产物；当前没有可用的 computer-use 原生
管道，未将其记作真实 WinUI 对话框操作或屏幕阅读器验收。
