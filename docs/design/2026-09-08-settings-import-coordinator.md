# 备份导入的应用层协调器

主控磁贴和设置页共用的备份导入入口此前在页面组合类中编排持久事务、配置
缓存失效、运行时应用、回滚和补偿。现在这些决策由 Application 层的
`SettingsImportCoordinator` 负责；页面只取得独占许可、连接适配器，并在明确
的恢复失败时请求重启。

导入与重置共用不可变 `SettingsRuntimeSnapshot`、运行时参与者端口和参与者
执行器。外部运行时仍通过原有已准入操作访问，存储仍是唯一 LocalSettings
authority；没有启用第二份设置文件写入或替换既有数据包事务格式。两个入口
保留各自的持久开始和恢复语义，底层保留收据继续拥有完整旧数据。

## 决策与所有权

- 持久导入前检查路径和取消，读取基线后再次检查取消。开始阶段由数据包服务
  自己执行校验和恢复；没有获得收据时，不虚构回滚或调用外部参与者。
- 获得收据后先使配置缓存失效，再读取导入后的设置。语言、主题、强调色、
  启动注册、采样和网络逐项尝试，非致命失败不会阻止其余参与者；最后核对
  持久快照仍然一致。所有后续应用、补偿及清理使用不可取消令牌。
- 应用或配置缓存失效失败时，先完成保留回滚，再重新使配置缓存失效。新增
  回滚后快照检查：只有完整旧设置确实恢复后才应用旧运行时；不完整回滚直接
  进入恢复状态，不把旧请求施加在未恢复的设置上。
- 应用成功后只完成同一个提交决定；清理失败重试不会改成回滚。回滚完成前
  不开始运行时补偿，回滚清理失败同样只重试该决定。
- 协调器等待收据释放后才结束，外层独占许可随后释放。收据释放异常保留原始
  错误图和导入恢复分类，使页面仍可请求重启。致命错误继续传播，不被普通
  清理异常降级。

协调器保留调用方上下文；原来导入入口在第一次异步数据导入后显式丢弃上下文，
现在主题和语言回调沿调用上下文执行。没有启动额外后台任务，文件选择器和
确认对话框仍由原有页面生命周期管理。
