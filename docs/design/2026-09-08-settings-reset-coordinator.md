# 设置重置的应用层协调器

全量、启动组及两个网络组的提交、参与者选择、补偿和收据清理此前集中在
SettingsViewModel。现在这些决策由 Application 层的 `SettingsResetCoordinator`
负责。它只依赖明确的操作端口、不可变运行时快照和保留收据，不引用页面、
LocalSettings、网络实现或应用单例。

页面仍负责排空已接受的命令、持有独占许可、串行化重置、显示错误和刷新整组
字段。轻量适配器将现有存储、外部参与者和页面状态通知接到应用端口；生产
持久化仍只有既有 LocalSettings authority，保留事务继续由数据包服务拥有。
没有启用并行 JSON 写入来源，也没有将此节点声明为完整设置代际迁移。

## 事务与失败边界

- 应用层只接受 All、Startup、Proxy、TransparentProxy 四个明确作用域，其他
  值在读取存储前拒绝。持久修改前检查取消，之后的参与者、决定重试和清理均
  不受页面取消中断。调用方继续持有整个操作的独占许可。
- 每个作用域选择自己的参与者；非致命异常不会阻止后续参与者尝试应用。协调器
  检查操作后仍是同一份持久快照，失败时先通过保留收据恢复存储，再补偿运行时。
  组重置不调用旧的全量设置恢复兼容入口。
- 提交与回滚只重试同一决定。确认应用成功后，状态观察者抛出的普通异常不能
  阻止已选定提交的清理；观察者和清理同时失败时保留两类诊断，不改成回滚。
- 重置完成后若无法读取目标设置，仍尝试保留回滚；部分写入失败或补偿过程中
  无法读取权威状态时返回明确的恢复异常，不能发布未读到的快照。
- 收据由协调器等待并释放，运行时许可随后由页面释放。收据释放失败保留原始
  错误图和恢复分类；ViewModel 仍能设置恢复状态并请求重启。致命错误图继续
  传播，普通清理异常不能把它降级为一般操作错误。

协调器保持调用方上下文，使现有主题和语言回调继续在页面上下文运行；它不
自行启动后台任务、关闭许可或请求重启。窗口及操作生命周期继续由原有边界
管理，既有页面整组通知与其他设置的重启提示基线保持。
