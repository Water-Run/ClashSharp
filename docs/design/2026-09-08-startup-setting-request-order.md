# 开机启动请求与保存顺序

开机启动开关会把连续修改合并到一个异步应用任务。此前设置方法先更新待应用
状态，再保存设置；若后一次保存抛出异常，待应用状态已经被替换，正在等待系统
调用结束的任务会继续应用这次未被保存接受的选择。

修复将保存放在待应用状态更新之前。保存失败会直接返回异常，原来已接受的任务
继续执行；显示值和待应用状态均保持。保存成功后，现有合并、取消和失败恢复机制
继续负责系统注册。本变更没有增加新的并发入口或更改 Windows StartupTask 权限。

两项回归覆盖相反的初始状态。先阻塞一项已接受的应用请求，再让相反选择的保存
失败，最后释放原任务。旧实现分别观察到 `[false, true]` 和 `[true, false]`
两次应用调用；修复后只调用已接受的第一个值，设置和页面保持一致。测试始终释放
阻塞点并等待任务结束，系统注册回调为模拟，没有修改开发机开机启动设置。

完整 format 检查 1404 个文件、0 处变更。证据为 `local-validation-m3g.json`、
`1.0.0-m3g-main.trx` 及 `artifacts/verification` 下对应构建、测试、格式日志。

这项结果验证请求顺序，不替代真实 Windows 开机启动权限及按组重置的运行时验收。
