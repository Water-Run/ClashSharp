# Clash# 原生 Agent / MCP 服务器

## 用户要求与完整交付范围

用户要求在设置中新增完整的「MCP 服务器」类别，提供开关与可配置授权范围，让 Agent 可以从状态查询、部分配置修改扩展到历史详情读取。切换代理状态必须有独立开关，避免需要外网的 Agent 意外断网。Agent 原生支持属于产品正式能力与卖点，不能仅展示一个设置占位区或工具列表。

当前实现状态：**开发中，尚未在安装中的产品启动 MCP 监听或开放业务操作**。Core 已实现八项独立范围、操作组合与通用设置写入分类；服务器完整重建零警告/错误，27 项检查及作用域格式通过，其中两项遍历启用/禁用与全部 256 种授权组合，共 5,120 个操作授权判定。最初的类型名称触发仓库 CA1711 规则，已改为 `McpAccessScope` 后重新验证，未关闭分析器。证据为 `mcp-server-20261015/validation-r2`。独立 HTTP 传输的进展见下文；设置分组、真实工具执行与产品生命周期仍待接通。

### 传输层接续

已实现独立的 `ClashSharp.Infrastructure.Mcp` 适配器程序集，只有主程序和测试引用，基础 Infrastructure 与 mihomo 服务不携带 ASP.NET/MCP 依赖。它提供官方 SDK 2.2.0 的 Streamable HTTP、固定回环地址、Host/Origin 校验、独立 bearer 验证、动态工具过滤和逐次调用检查，以及完整等待 HTTP/工具工作的停止与释放。监听器只保留凭据摘要，身份不携带原始令牌；未预期异常经脱敏后送入应用错误汇，原异常内容不返回客户端。

15 项工具定义覆盖状态、设置、配置、历史、诊断和代理控制，协议输入/输出均有大小界限。**目前接通的是传输和 Application 端口，实际产品业务后端、令牌持久化、设置类别与启动组合仍未接通**；测试中的业务结果来自隔离夹具，不能据此宣称 Agent 已可操作安装中的 Clash#。

通过用户提供的外网 SSH 入口继续验证，服务器身份和原服务核对一致。最终 `transport/validation-r5` 的 72 项测试通过、构建零警告/错误、作用域格式通过：包括官方客户端默认协议和 `2025-11-25` 的互操作、隐藏工具被直接调用时的拒绝、权限变更后的重新发现、旧令牌撤销、错误 Host/Origin、端口占用后重试、异常内容脱敏，以及取消停止等待后仍保留后台工作直至释放。新增环境变量用例证明宿主配置不能把监听改为 `0.0.0.0`。首轮 71 项通过后，该补充实现曾因移除全部配置源而使显式地址设置失败；补入专用内存配置源后全部 72 项通过，失败报告保留。隔离测试监听器均已正常释放，安装中的产品仍未启用 MCP。

接续实现应将启用、端口和八项范围保存到权威设置（范围可用经验证的位集合表示），增加从现有 schema 2 的加法迁移；权限及秘密不进入设置导出。随后连接 generation 内的业务操作、独立凭据存储和运行参与者，再接入完整 WinUI 类别。新依赖还需要准确 CI、离线材料和签名打包验证。

## 界面与连接

- 设置新增独立「MCP 服务器」分组，沿用 Win11 原生控件与现有扁平 SettingRow，提供启用开关、实际运行状态、端口、连接地址、复制客户端配置、重新生成访问令牌，以及逐项授权开关。
- 首次默认关闭。默认只授权基础状态读取；修改、历史、敏感内容和代理控制默认关闭。权限变更不需要重启整个应用，关闭服务器停止接收请求并等待已有工作退出。
- 使用固定版本的官方 C# SDK 和本机 Streamable HTTP。监听只绑定回环地址，验证 Host/Origin，所有 MCP 请求需要单独生成的高熵凭据。不会复用 mihomo 控制器凭据，也不会把令牌放入 URL、日志、设置导出包或源码。
- 复制的客户端配置包含明确端点和认证方式；界面说明服务跟随 Clash# 运行。权限和连接秘密属于本机授权，配置导入不能自动为 Agent 扩大权限。
- 八语言文案、辅助名称、窄窗口换行与固定操作按钮随正式实现完成。关于页的 Agent 支持说明只在服务实际接通后更新。

## 授权范围

| 授权 | 范围 |
|---|---|
| 读取状态 | 应用、核心、代理模式及服务状态，端点自身能力说明 |
| 读取配置 | 已允许设置和配置概要；普通响应排除访问令牌和节点凭据 |
| 修改配置 | 经过现有验证与事务提交的设置或非活动配置修改 |
| 读取诊断 | 有界、脱敏的日志与连接/诊断信息 |
| 读取历史概要 | 配置版本、采样及操作记录的分页概要 |
| 深入读取历史 | 按明确记录标识读取历史详情；不因此隐式取得敏感配置权限 |
| 读取敏感配置 | 与配置读取或历史详情授权共同使用，允许相应配置中的敏感字段 |
| 切换代理状态 | 启停、模式、节点/活动配置选择，以及会改变实际联网状态的配置提交 |

通用配置写入不能绕过代理控制开关。代理模式、活动配置、TUN、监听端口、启动/退出代理策略等都需要配置修改与代理控制两项授权。启用触发器可能间接改变代理，不能通过通用设置写入绕过控制；MCP 的启用、权限和凭据管理始终由用户在程序中操作，Agent 不得给自己授权。

未授权工具从发现列表过滤，但服务仍在每次调用及实际写入前检查权限；仅隐藏工具不足以构成授权。未知权限位、未知操作和未分类设置均拒绝。完整写入批次必须先验证每一项，再接入现有 generation 与 mutation admission，不能悄悄丢弃拒绝项后提交其余部分。权限撤销阻止新请求；正在执行的可取消工作接受取消，不宣称撤销已经提交的动作。

## 实现边界

Core 保存不可变权限和操作分类，Application 保存授权、工具用例及运行生命周期端口，Infrastructure 提供官方 MCP HTTP 传输、认证与凭据存储，WinUI composition 连接现有应用服务。工具不得绕过设置权威、直接修改私有文件、调用任意 shell、访问任意路径，或通过主窗口事件模拟产品命令。

MCP 服务属于当前数据代的受控运行参与者。退出、导入替换、全部清理与故障恢复必须停止接入、取消/等待工作后才释放旧代。真实运行状态须独立观察；端口占用、认证存储失败及启动失败通过设置页反馈，不能把“已保存启用”当作“正在监听”。审计仅记录工具标识、客户端安全标识、时间与结果，不记录凭据或原始私有参数。

复用现有 mutation admission：MCP 操作在普通准入和固定数据代内完成授权与业务动作，使用已准入的设置入口；MCP 启用、授权与令牌变化走排他准入，先排空旧请求，再发布新授权，不能在普通请求持有命令锁时反向等待排他权。旧协议会话也不得缓存权限。接入时需扩展现有 `RequiresProducerDrain` 与当前代运行组件组合，不能只在 HTTP 中间件检查一次令牌。

官方 [C# SDK 2.2.0](https://github.com/modelcontextprotocol/csharp-sdk/releases/tag/v2.2.0)为本轮核对的稳定版本，提供 .NET 10 的 ASP.NET Core 集成。传输按官方 [Streamable HTTP 规范](https://modelcontextprotocol.io/specification/draft/basic/transports/streamable-http)核对 Origin、回环绑定及协议版本兼容；最终依赖以锁文件和真实客户端互操作验证为准。

## 完成门槛

1. 设置分组、持久化/迁移、重置及导入隔离完整接通，默认关闭与默认权限有测试。
2. 官方 MCP 客户端能够发现服务器并执行获准的真实读写用例；读状态、配置修改、历史详情和代理控制均有实际可用工具，而非仅声明接口。
3. 未授权、错误凭据、错误 Origin/Host、未知工具/设置、间接代理变更和 Agent 自授权均在副作用前拒绝；合法与拒绝路径都核对产品状态。
4. 动态权限、令牌轮换、关闭、端口冲突、应用退出及数据代替换的生命周期验证完成，旧连接不能保留已撤销的权限。
5. 分页、大小限制、脱敏、取消、超时及写入重试语义验证完成，私有内容不进入测试报告。
6. 服务器和 CI 构建/测试/签名包通过，新增依赖进入离线打包与第三方材料校验；本机不执行产品测试。
7. 准确签名包完成 WinUI 设置页与 Agent 联调，核对明暗主题、最小窗口及权限开关后更新产品说明。此前的开关轮廓、颜色选择器与语言实图复验继续保留。
