# 连接采样设置与循环生命周期事务

设置页此前先分别保存开关、间隔，再调用读取当前设置的重启回调。应用动作
已经无法取得修改前的开关基线；失败时页面又用自己的旧值写回两项设置，可能
覆盖后端结果。四项回归在旧实现上复现了提前保存和覆盖权威结果的问题。

现在 Application 层的 `ConnectionSamplingSettingsCoordinator` 统一协调普通
页面、应用动作及触发器。页面传入完整的不可变开关/间隔，应用动作和触发器
的仅开关操作则在串行化后读取最新间隔，避免把排队前的旧间隔写回。它与重置、
导入和退出共享准入；触发器复用并保持自己的许可，构造函数不读设置或启动循环。

## 提交与补偿

- 取得操作权后读取完整偏好快照及循环实际运行状态，两项基线独立保存。
- 先通过 Quiesce 暂停并排空循环，确认它已停止，再在原 AppSettingsService
  中批量提交两个字段；重读确认完整结果后，按目标开关启动并确认循环状态。
- 暂停使用可恢复的生命周期操作，保留后续重新开启的能力。Stop 仍只用于
  应用终止；协调器不能把已永久停止的循环报告为成功启用。
- 暂停开始前响应取消和准入撤销；开始后完整等待提交或补偿，不留下被页面
  取消遗弃的循环任务。关闭准入等待本次事务排空。
- 非致命失败重新暂停循环、恢复并验证旧偏好，再恢复原实际运行状态。若暂停
  或旧设置无法确认，不继续启动；`ConnectionSamplingSettingsRecoveryException`
  保留原始失败与恢复失败。致命错误图继续传播。

原存储新增整组读取接口，在批量写入的同一把锁下读取。页面只暂存选择，成功或
失败后读取这一权威快照，两个显示字段准备完成后再发通知，不做页面补偿写入。
连续操作合并为最新完整选择，命令完成间隙的请求任务也纳入重置前的排空。
旧同步测试回调仅在 UNIT_TESTS 中保留；生产页面必须提供完整异步应用回调。

重置和导入仍使用独占许可下原有的外部运行时参与者。本轮没有另建设置存储或
启用 JSON 双写；普通采样协调器负责进程内提交和补偿，不代表完成了跨进程的
设置代际恢复。完整设置 authority 迁移仍待整体切换。
