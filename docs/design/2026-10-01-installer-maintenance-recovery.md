# 安装维护恢复的事务边界

目标是在安装维护已经影响机器状态后提供可验证的产品恢复，保留[软件包原生预检查](../reviews/2026-10-01-native-package-preflight-acceptance.md)已经证明的开始前拒绝。开始前拒绝不能代替中途恢复，本设计也不把服务重新启动等同于整个安装事务恢复完成。

## 最终行为

包尚未替换时，用户可以选择保留原安装。恢复只能使用首次机器准备之前持久记录的原安装基线，重新证明原包身份和内容、全部机器载荷、机器关联以及证书归属保持一致，再恢复原服务配置、权限和运行状态。任何证据缺失、基线过期、文件变化、外部替换或状态无法确认，都保留恢复事务，拒绝宣称还原完成。

包已经提交，或无法证明包仍为原包时，使用准确相同候选继续完成更新。没有旧签名载荷及完整归属证据时，不提供任意降级或从缓存拼装旧包的恢复。后续如支持包提交后的回滚，应先保留并验证旧签名载荷、引用、机器基线和独立回滚日志，再扩大此边界。

Prepared 或 MachineReserved 阶段本身不能证明包未改变：AppXSVC 可能已经部署而回复或阶段保存丢失。因此恢复决定必须核对当前实际包及原内容，不仅检查阶段。提交后的取消不能释放仍执行或复核 SCM 写入的 helper、权限或目录租约。

## 已实现的基础能力

`WindowsServicePreparationBaseline` 只接受准确 Repair 的 Prepared 初始意图、已知安全且归属准确的服务，以及 Running/Stopped 的稳定运行状态。配置、DACL、事务身份和候选身份绑定；PID 不作为恢复身份。恢复边界仅允许同一意图的 Prepared/MachineReserved，PackageCommitted 或另一事务/候选被拒绝。规范 JSON 拒绝缺失、重复、未知、非规范或超限内容，配置依赖复制为只读集合。

基线包含服务命令行内的 IPC 凭据，仅能进入 `InstallerAuthority/v1` 的受保护私有文件，不能放入父进程 IPC、普通恢复日志、界面、诊断或公开资产。序列化及 I/O 临时字节在使用后清零；错误只返回不含秘密的稳定诊断。

`WindowsServicePreparationBaselineStore` 依次使用只读/写入目录 guard 和固定普通私有文件能力。首次捕获持久化后才可使用；准确重放零写入，其他原始观察或事务不能覆盖首次基线。写入异常或取消后，在不取消的重读中核对结果，不能以写入回执是否成功决定基线存在。此本地 gate 不替代认证 helper 的跨进程机器排他权限。暂不提供基线删除能力，避免尚未完成的终结协议丢失恢复证据。

`WindowsServiceMutation.RestorePreparedBaselineAsync` 要求显式的原安装验证 guard。验证失败前零 SCM 写入；只接受准确已恢复状态，或归属准确、Stopped/Disabled/准备 DACL 的服务。配置恢复后再次核对原安装，再决定是否启动；最后独立核对完整配置、DACL和稳定运行状态。准确已恢复状态可重放，不用旧 PID 判断成功。SCM 回执丢失或提交后 UI 取消仍完成有限时间的后置观察；无法证明结果返回不确定状态。

上述能力尚未加入生产 helper 的准备/恢复流程，不新增可点击的恢复按钮。需要下面的接入后才具有用户可用的恢复功能；旧 Windows 服务和安装器权限未放宽。

## 必须完成的接入和验收

1. 在首次服务准备之前，捕获实际原包、原载荷、关联和证书证据，结合服务基线写入同一认证私有恢复记录。重放必须读取首次记录，不能把已准备的服务当作原状态。
2. 提供原安装验证 guard，持有准确跨进程排他、App 屏障和目录/文件租约；在恢复前、配置后和最终复核中证明上述证据仍成立。服务凭据不跨父进程边界。
3. 增加明确的恢复决定及可重启私有恢复阶段。公共事务只有在所有原安装后置条件及对应私有状态核对完成后才能终结；回复丢失、终结失败和重启必须可恢复，不能通过直接删除 Prepared 文件完成。
4. 为正确 Repair 暂停提供“保留原安装”入口；阶段不支持或证据不全时解释需要同候选继续。原有安装、账户迁移和旧账户卸载的权限不能被新入口扩大。
5. 用隔离服务器验证服务准备前后、包提交边界、配置写入和启动回执丢失、取消、进程退出及重启。把每次机器状态、原包/文件/证书保留、无事务残留以及应用再次可启动作为独立证据；模拟回归不关闭这组要求。

全项目目标还包括证书轮换、活动网络下数据维护、窗口状态、完整功能矩阵和正式发行。此基础检查点不缩减这些要求，也不声明生产恢复已完成。
