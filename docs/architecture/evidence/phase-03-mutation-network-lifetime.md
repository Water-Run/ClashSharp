The first lifecycle-focused test build failed with `CS0234`/`CS0246` because `ClashSharp.ApplicationModel.Lifecycle`, `IRuntimeParticipant`, `RuntimeLifecycleCoordinator`, and the outer lifetime request contracts did not exist. The implemented coordinator now closes and drains ordinary mutation admission, quiesces ordered producers under a 30-second default deadline, restores successful pauses in reverse order on pre-commit failure, executes the shutdown network policy under the already-drained lease, makes admission terminal only after the network target commits, and stops participants in reverse order before returning `PreparedForHostDisposal`. Recovery-only exit waits for the existing recovery handoff and deliberately skips a competing network mutation.

Exit and restart are now single-winner requests to an App-owned channel. Trigger, Settings, tray, and window UI return after handoff; none stops the host, calls `Environment.Exit`, or closes the WinUI window as an exit mechanism. `App` consumes the request on its dispatcher, `ProcessLifetimeRunner` awaits real host shutdown and only then disposes once, and restart launch occurs afterward. A failed host stop no longer disposes services underneath an unprepared runtime. The old synchronous `RuntimeShutdownService` and its window-close bypass were removed.

Structured review and focused regressions found four additional concurrency defects. An already-satisfied network target was indistinguishable from its baseline and incorrectly compensated; participant classification is now execution-phase aware and committed recovery uses the journal marker to resolve equivalence. Trigger event admission could race between its acceptance check and drain registration; direct, periodic, and runtime-event evaluation now share the lifecycle lock. Immediate sampling start/stop captured a nullable or disposed `CancellationTokenSource` field in the background lambda; the loop now captures the token value and lifecycle quiescence blocks replacement starts until resume. Finally, native window close previously destroyed the only window before shutdown could report an abort; close is now cancelled while the outer request is prepared, with duplicate confirmation dialogs suppressed.
